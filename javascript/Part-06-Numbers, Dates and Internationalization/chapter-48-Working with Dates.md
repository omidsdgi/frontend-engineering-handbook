مقدمه

تقریباً هر Application واقعی با زمان سروکار دارد.

یک فروشگاه باید زمان ثبت Order را ذخیره کند. یک سیستم بانکی باید زمان Transaction را ثبت کند. یک Application رزرو باید تاریخ شروع و پایان Reservation را بداند.

در نگاه اول ممکن است تصور کنیم تاریخ فقط مجموعه‌ای از مقادیر مانند سال، ماه، روز و ساعت است.

اما در JavaScript مسئله کمی متفاوت است.

برای اینکه بتوانیم با Date به‌درستی کار کنیم، ابتدا باید بدانیم JavaScript در اصل چه چیزی را در یک Date نگهداری می‌کند.

Date در JavaScript

فرض کنید می‌خواهیم زمان فعلی را در اختیار داشته باشیم:

const now = new Date();

در اینجا now یک Object از نوع Date است.

now
↓
Date Object

این Object امکان ایجاد، خواندن، مقایسه و تبدیل مقادیر مربوط به زمان را فراهم می‌کند.

اما نکته مهم این است که Date صرفاً یک مجموعه ساده از:

year
month
day
hour
minute
second

نیست.

یک Date در JavaScript در اصل یک مقدار زمانی را نمایش می‌دهد که موقعیت یک لحظه مشخص در زمان را مشخص می‌کند.

برای همین مفهوم دیگری اهمیت پیدا می‌کند:

Timestamp

Timestamp

برای نمایش یک لحظه مشخص در زمان، JavaScript از یک مقدار عددی استفاده می‌کند.

این مقدار تعداد Millisecondهای گذشته از:

1970-01-01 00:00:00 UTC

است.

این نقطه را Unix Epoch یا Epoch می‌نامیم.

برای مثال:

const now = new Date();

console.log(now.getTime());

متد getTime() Timestamp مربوط به Date را برمی‌گرداند.

بنابراین می‌توانیم مدل ذهنی زیر را داشته باشیم:

Date
↓
Timestamp
↓
Number of milliseconds from Epoch

این مدل اهمیت زیادی دارد، زیرا مقایسه دو Date در نهایت به مقایسه دو مقدار زمانی تبدیل می‌شود.

مثلاً:

const start = new Date('2026-09-01');
const end = new Date('2026-09-10');

console.log(end > start);

نتیجه:

true

زیرا end نشان‌دهنده لحظه‌ای بعد از start است.

پس برای مقایسه Dateها لازم نیست اجزای سال، ماه و روز را جداگانه مقایسه کنیم.

خود Date این مفهوم را برای ما مدل می‌کند.

ایجاد Date

اکنون که می‌دانیم Date یک Object برای نمایش یک لحظه زمانی است، سؤال بعدی این است:

چگونه یک Date ایجاد کنیم؟

ساده‌ترین روش استفاده از new Date() است.

const now = new Date();

در این حالت Date مربوط به زمان فعلی ایجاد می‌شود.

می‌توانیم یک Timestamp نیز به Constructor بدهیم:

const date = new Date(0);

مقدار 0 به معنی لحظه Epoch است.

همچنین می‌توانیم یک Date را با استفاده از اجزای آن ایجاد کنیم:

const date = new Date(2026, 8, 17);

در این روش باید به یک نکته مهم توجه کنیم:

Month در Constructor از صفر شروع می‌شود.

بنابراین:

0  → January
1  → February
...
8  → September

پس مقدار 8 در مثال بالا به معنی September است، نه August.

این یکی از خطاهای رایج هنگام کار با Date است.

ایجاد Date از String

روش دیگری که در Applicationهای واقعی زیاد دیده می‌شود، ایجاد Date از یک String است:

const date = new Date('2026-09-17');

این روش به‌خصوص هنگام دریافت داده از API یا ذخیره‌سازی تاریخ‌ها کاربرد دارد.

اما اینجا باید یک اصل مهم را به خاطر داشته باشیم:

هر String شبیه تاریخ، الزاماً یک Date قابل اعتماد نیست.

فرمت‌های استاندارد باید ترجیح داده شوند.

برای مثال:

new Date('2026-09-17');

قابل پیش‌بینی‌تر از فرمت‌های غیر استاندارد است.

Parsing فرمت‌های غیر استاندارد می‌تواند بین محیط‌های مختلف رفتار متفاوتی داشته باشد.

بنابراین در Applicationهای واقعی نباید صرفاً به این دلیل که یک String شبیه تاریخ است، آن را قابل اعتماد فرض کنیم.

خواندن اجزای Date

گاهی Timestamp برای ما کافی نیست.

ممکن است بخواهیم بدانیم یک Date مربوط به چه سال، ماه یا ساعتی است.

برای این کار Date متدهایی مانند این‌ها دارد:

const date = new Date();

date.getFullYear();
date.getMonth();
date.getDate();
date.getDay();
date.getHours();
date.getMinutes();
date.getSeconds();

هر متد بخش مشخصی از Date را برمی‌گرداند.

برای مثال:

const date = new Date();

console.log(date.getFullYear());
console.log(date.getMonth());
console.log(date.getDate());

نکته مهم این است که متدهای get... معمولاً اجزای Date را بر اساس Local Time Zone محیط اجرا برمی‌گردانند.

در مقابل، Date متدهای getUTC... نیز دارد:

date.getUTCFullYear();
date.getUTCMonth();
date.getUTCDate();
date.getUTCHours();

این متدها همان لحظه را بر اساس UTC می‌خوانند.

پس:

get...
↓
Local Time

getUTC...
↓
UTC

این تفاوت زمانی اهمیت پیدا می‌کند که Application در Time Zoneهای مختلف اجرا شود.

Formatting یک Date

تا اینجا Date را ایجاد کرده‌ایم و اجزای آن را خوانده‌ایم.

اما در Application معمولاً نمی‌خواهیم Date را فقط به‌عنوان Object نگه داریم.

باید آن را به یک String قابل نمایش یا قابل انتقال تبدیل کنیم.

یکی از روش‌های مهم:

const date = new Date();

console.log(date.toISOString());

toISOString() یک String در قالب استاندارد ISO تولید می‌کند و زمان را در UTC نمایش می‌دهد.

نمونه:

2026-09-17T08:30:00.000Z

حرف Z در انتهای String نشان می‌دهد که زمان بر اساس UTC بیان شده است.

برای نمایش Local Time می‌توان از روش‌هایی مانند:

date.toString();

استفاده کرد.

همچنین:

date.toUTCString();

یک نمایش String بر اساس UTC ارائه می‌کند.

بنابراین باید میان دو هدف تفاوت قائل شویم:

Data Representation
vs.
User Display

یک Date ممکن است برای ذخیره یا انتقال با ISO Format مناسب باشد، اما همان مقدار برای نمایش به کاربر ممکن است نیاز به Format دیگری داشته باشد.

Formatting پیشرفته و وابسته به Locale در فصل Intl بررسی خواهد شد.

Date و محاسبات زمانی

یکی از مزیت‌های مهم Timestamp این است که محاسبات زمانی را ساده می‌کند.

فرض کنید می‌خواهیم مدت زمان بین دو Date را محاسبه کنیم:

const start = new Date('2026-09-01');
const end = new Date('2026-09-10');

const difference = end - start;

console.log(difference);

نتیجه بر حسب Millisecond خواهد بود.

اگر بخواهیم آن را به روز تبدیل کنیم:

const days = difference / (1000 * 60 * 60 * 24);

در نتیجه:

Date
↓
Timestamp
↓
Arithmetic

این مدل برای محاسبه فاصله زمانی بسیار کاربردی است.

برای مثال می‌توان از آن برای محاسبه:

مدت زمان یک Session
فاصله بین دو Event
مدت اعتبار یک Token
زمان باقی‌مانده تا یک Deadline

استفاده کرد.

تغییر دادن Date

Date یک Object قابل تغییر است.

برای مثال:

const date = new Date();

date.setFullYear(2027);

در اینجا همان Date Object تغییر می‌کند.

Date متدهای Setter مختلفی دارد:

setFullYear()
setMonth()
setDate()
setHours()
setMinutes()
setSeconds()

همچنین نسخه‌های UTC آن‌ها نیز وجود دارند.

این قابلیت در بعضی شرایط مفید است، اما باید مراقب Mutation باشیم.

اگر چند بخش Application به یک Date Object مشترک دسترسی داشته باشند، تغییر آن Object می‌تواند روی بخش‌های دیگر نیز اثر بگذارد.

بنابراین در کدی که State یا Data بین بخش‌های مختلف به اشتراک گذاشته می‌شود، بهتر است Mutation را آگاهانه انجام دهیم.

Date و Time Zone

اینجا به یکی از مهم‌ترین قسمت‌های کار با Date می‌رسیم.

فرض کنید یک کاربر در تهران و کاربر دیگری در لندن یک Event مشخص را مشاهده می‌کنند.

آیا باید دو لحظه متفاوت ذخیره کنیم؟

خیر.

اگر هر دو به یک Event واقعی اشاره کنند، باید یک لحظه یکسان در زمان داشته باشیم.

آنچه می‌تواند متفاوت باشد، نحوه نمایش آن لحظه در Time Zone هر کاربر است.

مدل ذهنی مناسب این است:

One Instant
↓
UTC-based Time Value
↓
Local Representation
├── Tehran
├── London
└── New York

بنابراین یک لحظه مشخص می‌تواند در Time Zoneهای مختلف با ساعت‌های متفاوت نمایش داده شود.

این موضوع یکی از مهم‌ترین دلایل جدا کردن مفهوم Instant از Local Representation است.

Local Time و UTC

در JavaScript بسیاری از متدهای Date از Local Time Zone محیط اجرا استفاده می‌کنند.

برای مثال:

date.getHours();

ساعت را بر اساس Local Time Zone برمی‌گرداند.

در مقابل:

date.getUTCHours();

همان لحظه را بر اساس UTC می‌خواند.

پس اگر این دو مقدار متفاوت باشند، لزوماً Date متفاوتی نداریم.

ممکن است فقط دو روش مختلف برای مشاهده یک لحظه را استفاده کرده باشیم.

برای بررسی اختلاف Local Time با UTC می‌توان از:

date.getTimezoneOffset();

استفاده کرد.

این متد اختلاف زمانی Local Time و UTC را بر اساس دقیقه گزارش می‌کند.

اما علامت این مقدار ممکن است در نگاه اول غیرمنتظره باشد؛ بنابراین نباید بدون درک قرارداد آن، مقدار را مستقیماً به‌عنوان «UTC منهای Local» یا برعکس تفسیر کرد.

یک مشکل مهم در Date Parsing

یکی از رایج‌ترین خطاها این است که Date را با Stringهای نامطمئن ایجاد کنیم.

مثلاً:

new Date('09/17/2026');

ممکن است در محیط‌های مختلف رفتار مورد انتظار را نداشته باشد.

برای همین در Applicationهای واقعی بهتر است داده‌های زمانی با فرمت استاندارد و مشخص منتقل شوند.

فرمت ISO یکی از انتخاب‌های رایج است:

2026-09-17T12:30:00.000Z

در اینجا علاوه بر تاریخ و زمان، اطلاعات مربوط به UTC نیز مشخص است.

این موضوع مخصوصاً هنگام کار با API اهمیت زیادی دارد.

اگر Server و Client در Time Zoneهای مختلف باشند، فرمت مبهم می‌تواند باعث شود یک Event در زمان متفاوتی نمایش داده شود.

Invalid Date

گاهی JavaScript نمی‌تواند یک Date معتبر ایجاد کند.

برای مثال:

const date = new Date('invalid-date');

در این حالت Object همچنان از نوع Date است، اما مقدار زمانی معتبر ندارد.

برای بررسی اعتبار Date می‌توان از:

date.getTime();

استفاده کرد.

اگر نتیجه:

NaN

باشد، Date معتبر نیست.

بنابراین صرفاً این بررسی کافی نیست:

date instanceof Date

زیرا ممکن است Object از نوع Date باشد اما مقدار زمانی آن Invalid باشد.

Date در Application واقعی

اکنون می‌توانیم Date را در یک Application واقعی بهتر تحلیل کنیم.

فرض کنید API یک Order را برمی‌گرداند:

{
id: 42,
createdAt: '2026-09-17T08:30:00.000Z'
}

String دریافتی را می‌توان به Date تبدیل کرد:

const createdAt = new Date(order.createdAt);

از اینجا به بعد Application می‌تواند:

Date
↓
Comparison
↓
Calculation
↓
Formatting

را انجام دهد.

مثلاً می‌توانیم مشخص کنیم آیا Order مربوط به امروز است، چند ساعت از ثبت آن گذشته یا آن را برای کاربر به شکل مناسب نمایش دهیم.

نکته مهم این است که ذخیره‌سازی، پردازش و نمایش Date سه مسئله متفاوت هستند.

ممکن است یک Format برای انتقال داده مناسب باشد، اما همان Format برای نمایش به کاربر مناسب نباشد.

Date راهی برای کار با یک مقدار زمانی است و اجزای قابل مشاهده مانند سال، ماه، روز و ساعت می‌توانند بر اساس Time Zone متفاوت باشند.

این تفاوت زمانی بسیار مهم است که Application در محیط‌های مختلف اجرا شود.

Best Practices
1. برای انتقال زمان از Format مشخص استفاده کنید

در APIها و سیستم‌های توزیع‌شده، فرمت‌های استاندارد مانند ISO انتخاب مناسبی هستند.

2. Instant را از Display جدا کنید

زمان ذخیره‌شده و نحوه نمایش آن به کاربر یک مسئله نیستند.

3. هنگام کار با Date، Time Zone را نادیده نگیرید

کدی که روی سیستم شما درست کار می‌کند ممکن است در Time Zone دیگری رفتار متفاوتی نشان دهد.

4. به Month صفرمبنا توجه کنید

در Constructor، January برابر 0 است.

5. از Dateهای Mutable آگاه باشید

Setterهای Date همان Object را تغییر می‌دهند.

6. Date Parsing مبهم را استفاده نکنید

به فرمت‌های استاندارد و مشخص ترجیح بدهید.

Summary

JavaScript برای کار با زمان و تاریخ از Date استفاده می‌کند.

یک Date یک Object است که یک لحظه مشخص در زمان را نمایش می‌دهد. این لحظه را می‌توان به‌صورت یک Timestamp نیز در نظر گرفت؛ مقداری عددی که بر اساس Millisecond از Epoch بیان می‌شود.

Date را می‌توان با زمان فعلی، Timestamp، اجزای تقویمی یا Stringهای مناسب ایجاد کرد.

برای خواندن اجزای Date از متدهای get... و برای خواندن آن‌ها بر اساس UTC از متدهای getUTC... استفاده می‌کنیم.

Dateها را می‌توان به Stringهایی مانند ISO Format تبدیل کرد و Timestampها امکان مقایسه و محاسبه فاصله زمانی را فراهم می‌کنند.

در نهایت، بخش مهم کار با Date در Applicationهای واقعی، درک تفاوت میان Instant، Local Time و UTC است.

Technical Interview
Junior
1. Date در JavaScript چیست؟

Date یک Object برای نمایش و پردازش یک لحظه مشخص در زمان است.

2. Timestamp چیست؟

Timestamp مقدار عددی زمان است که در JavaScript بر اساس Millisecond از Epoch بیان می‌شود.

3. چگونه Date فعلی را ایجاد می‌کنیم؟

با:

const now = new Date();
4. آیا Month در Constructor از 1 شروع می‌شود؟

خیر. Month از 0 شروع می‌شود؛ بنابراین January برابر 0 و December برابر 11 است.

5. چگونه Timestamp یک Date را دریافت می‌کنیم؟

با:

date.getTime();
Mid-Level
6. تفاوت getHours() و getUTCHours() چیست؟

getHours() ساعت را بر اساس Local Time Zone و getUTCHours() ساعت را بر اساس UTC برمی‌گرداند.

7. چرا مقایسه دو Date ساده‌تر از مقایسه دستی سال و ماه و روز است؟

زیرا Date یک مقدار زمانی را نمایش می‌دهد و می‌توان آن را بر اساس Timestamp مقایسه کرد.

8. چرا Date Stringهای غیر استاندارد مشکل‌ساز هستند؟

زیرا Parsing آن‌ها می‌تواند به رفتار وابسته به محیط و پیاده‌سازی منجر شود. فرمت‌های استاندارد و مشخص قابل اعتمادتر هستند.

9. toISOString() چه نوع زمانی را نمایش می‌دهد؟

یک String استاندارد بر اساس UTC تولید می‌کند که معمولاً با Z پایان می‌یابد.

10. چگونه یک Date نامعتبر را تشخیص می‌دهیم؟

می‌توان Timestamp آن را بررسی کرد:

Number.isNaN(date.getTime());
Senior
11. چرا Time Zone در Applicationهای واقعی اهمیت دارد؟

زیرا یک Instant یکسان می‌تواند در Time Zoneهای مختلف با Local Time متفاوت نمایش داده شود. اگر Application این تفاوت را نادیده بگیرد، ممکن است زمان Eventها در Clientهای مختلف نادرست نمایش داده شود.

12. چرا بهتر است Instant و Display را از یکدیگر جدا کنیم؟

زیرا Instant باید یک لحظه مشخص و قابل اعتماد را نشان دهد، در حالی که Display باید بر اساس نیاز کاربر و Locale یا Time Zone مناسب تولید شود.

13. مهم‌ترین خطر هنگام کار با Date String چیست؟

فرض کردن اینکه هر String شبیه تاریخ، یک نمایش استاندارد و بدون ابهام از یک لحظه مشخص است. Parsing مبهم می‌تواند باعث اختلاف زمانی یا رفتار متفاوت در محیط‌های مختلف شود.

14. آیا Date فقط یک Calendar Date را نگهداری می‌کند؟

خیر. مدل Date بر یک مقدار زمانی مشخص متمرکز است. نمایش آن به شکل سال، ماه، روز و ساعت می‌تواند بر اساس Time Zone متفاوت باشد.

Golden Answers
اگر در مصاحبه پرسیدند: Date چیست؟

Date یک Object در JavaScript است که یک لحظه مشخص در زمان را نمایش می‌دهد و امکان ایجاد، خواندن، مقایسه، محاسبه و تبدیل آن را فراهم می‌کند.

اگر پرسیدند: Timestamp چیست؟

Timestamp یک مقدار عددی برای نمایش یک لحظه زمانی است که در JavaScript بر اساس Millisecond نسبت به Epoch بیان می‌شود.

اگر پرسیدند: تفاوت Local Time و UTC چیست؟

UTC یک مبنای زمانی مستقل از Local Time Zone است، در حالی که Local Time نمایش همان لحظه بر اساس Time Zone محیط اجرا است. بنابراین یک Instant می‌تواند در Time Zoneهای مختلف ساعت متفاوتی داشته باشد.

اگر پرسیدند: مهم‌ترین مشکل کار با Date چیست؟

یکی از مهم‌ترین مشکلات، اشتباه گرفتن یک Instant با نحوه نمایش آن و نادیده گرفتن Time Zone است. همچنین Date Parsing با فرمت‌های غیر استاندارد می‌تواند رفتار غیرقابل پیش‌بینی ایجاد کند.

Conclusion

کار با Date در JavaScript فقط یادگیری چند متد مانند getFullYear() یا toISOString() نیست.
