Core Question

چه زمانی Number برای نمایش Integerهای بزرگ کافی نیست؟

مقدمه

در بیشتر Applicationها، Number تمام نیازهای عددی ما را برطرف می‌کند. قیمت محصول، تعداد کالا، امتیاز کاربر یا مقدار یک محاسبه معمولی را می‌توان بدون مشکل با Number نمایش داد.

const price = 1200;
const quantity = 3;

const total = price * quantity;

اما همه Integerها در محدوده‌ای قرار نمی‌گیرند که Number بتواند آن‌ها را با دقت کامل نمایش دهد.

فرض کنید یک Application باید یک شمارنده بسیار بزرگ، یک شناسه عددی یا نتیجه یک محاسبه را بدون هیچ‌گونه تغییر در مقدار نگهداری کند. در این حالت، صرفاً Number بودن مقدار کافی نیست؛ باید بدانیم آیا Number هنوز می‌تواند آن Integer را دقیقاً نمایش دهد یا خیر.

برای درک این مسئله، ابتدا باید محدوده‌ای را بشناسیم که Number در آن برای Integerها قابل اعتماد است.

وقتی Number برای Integer کافی نیست

Integer عددی است که بخش اعشاری ندارد:

..., -3, -2, -1, 0, 1, 2, 3, ...

JavaScript این مقادیر را معمولاً با نوع Number نمایش می‌دهد. اما Number یک نوع عددی مبتنی بر استاندارد IEEE 754 double-precision floating-point است و نمی‌تواند تمام Integerهای ممکن را با دقت کامل نمایش دهد.

محدوده مهم برای Integerهای دقیق با مفهوم Safe Integer مشخص می‌شود.

بزرگ‌ترین Safe Integer در JavaScript از طریق Number.MAX_SAFE_INTEGER در دسترس است:

Number.MAX_SAFE_INTEGER;

مقدار آن:

9007199254740991

است.

برای بررسی اینکه یک Integer در این محدوده قرار دارد، می‌توان از Number.isSafeInteger() استفاده کرد:

Number.isSafeInteger(9007199254740991);

نتیجه:

true

اما:

Number.isSafeInteger(9007199254740992);

نتیجه:

false

مسئله این نیست که Number ناگهان از یک عدد خاص به بعد دیگر نمی‌تواند هیچ Integerی را نگه دارد. مسئله این است که از محدوده Safe Integer به بعد، Number نمی‌تواند همه Integerها را به‌صورت دقیق و متمایز نمایش دهد.

برای مثال:

const value = 9007199254740993;

ممکن است کد از نظر Syntax کاملاً معتبر باشد، اما نمی‌توان انتظار داشت Number این مقدار را با دقت Integer موردنظر حفظ کند.

بنابراین وقتی دقت Integer اهمیت دارد، باید علاوه بر بزرگی عدد، قابلیت Number برای نمایش دقیق آن را نیز در نظر بگیریم.

این محدودیت یک سؤال طبیعی ایجاد می‌کند:

اگر Number برای Integerهای بسیار بزرگ همیشه دقیق نیست، JavaScript چه راه‌حلی برای نگهداری و محاسبه دقیق آن‌ها ارائه می‌کند؟

پاسخ، BigInt است.

BigInt؛ راه‌حل Integerهای بزرگ

BigInt یک Primitive Type در JavaScript است که برای نمایش Integerهای با دقت دلخواه طراحی شده است.

بنابراین اگر Application به یک Integer بسیار بزرگ نیاز داشته باشد و حفظ مقدار دقیق آن مهم باشد، می‌توان به جای Number از BigInt استفاده کرد.

برای مثال:

const orderId = 9007199254740993n;

حرف n در انتهای مقدار نشان می‌دهد که این Literal از نوع BigInt است.

در نتیجه این دو مقدار، با وجود شباهت ظاهری، یک Type ندارند:

const numberValue = 100;
const bigIntValue = 100n;
typeof numberValue;
typeof bigIntValue;

نتیجه:

"number"
"bigint"

پس BigInt شکل دیگری از نوشتن Number نیست؛ یک Primitive Type مستقل است که مسئله مشخصی را حل می‌کند: نمایش و محاسبه دقیق Integerهای بزرگ.

این نکته مهم است، زیرا BigInt قرار نیست جایگزین Number در تمام Application شود. اگر با قیمت، درصد، اندازه‌گیری یا سایر مقادیر اعشاری کار می‌کنیم، Number همچنان انتخاب طبیعی است. 
BigInt Literals

بعد از اینکه مشخص شد BigInt برای نمایش Integerهای بزرگ با دقت بالا استفاده می‌شود، سؤال بعدی این است که JavaScript چگونه از همان ابتدا تشخیص می‌دهد یک مقدار از نوع BigInt است.

برای این منظور، JavaScript یک BigInt Literal دارد. با قرار دادن n در انتهای یک Integer Literal، مقدار نوشته‌شده به‌عنوان BigInt در نظر گرفته می‌شود:

const userId = 9007199254740993n;

در این مثال، n بخشی از Syntax مربوط به Literal است و نشان می‌دهد مقدار 9007199254740993 از نوع BigInt است.

تفاوت آن با یک Number Literal را می‌توان به‌صورت مستقیم مشاهده کرد:

const numberValue = 100;
const bigIntValue = 100n;

مقدار 100 یک Number و مقدار 100n یک BigInt است:

typeof numberValue;   // "number"
typeof bigIntValue;   // "bigint"

نکته مهم این است که n بخشی از مقدار عددی نیست؛ بلکه علامتی در Syntax Literal است که نوع مقدار را مشخص می‌کند.

اکنون که نحوه نوشتن یک BigInt Literal را می‌دانیم، می‌توانیم بررسی کنیم که عملیات حسابی روی این نوع داده چگونه انجام می‌شود.

محاسبه با BigInt

BigInt از عملگرهای اصلی حسابی برای Integerها پشتیبانی می‌کند.

const a = 20n;
const b = 5n;

console.log(a + b);
console.log(a - b);
console.log(a * b);

نتیجه:

25n
15n
100n

تقسیم نیز امکان‌پذیر است:

console.log(7n / 2n);

نتیجه:

3n

دلیل آن این است که BigInt فقط برای Integerهاست و نمی‌تواند بخش اعشاری نتیجه را نگهداری کند. بنابراین بخش اعشاری در تقسیم BigInt حذف می‌شود.

عملگرهای % و ** نیز قابل استفاده هستند:

10n % 3n;
2n ** 3n;

نتیجه:

1n
8n

در اینجا یک مرز مهم میان Number و BigInt ظاهر می‌شود.

مرز میان Number و BigInt

فرض کنید یک Application بخشی از داده را به صورت Number و بخشی دیگر را به صورت BigInt در اختیار دارد:

const itemCount = 10;
const largeCount = 20n;

ممکن است طبیعی به نظر برسد که آن‌ها را مستقیماً با هم جمع کنیم:

itemCount + largeCount;

اما JavaScript این عملیات را مجاز نمی‌داند و TypeError ایجاد می‌کند.

دلیل این رفتار آن است که Number و BigInt دو Type متفاوت با مدل عددی متفاوت هستند. JavaScript در عملیات حسابی، تبدیل ضمنی آن‌ها را انجام نمی‌دهد.

بنابراین:

10 + 20;

معتبر است و نتیجه یک Number است.

همچنین:

10n + 20n;

معتبر است و نتیجه یک BigInt است.

اما:

10 + 20n;

معتبر نیست.

در نتیجه هنگام طراحی یک محاسبه، باید مشخص باشد که مقدارها در کدام مدل عددی قرار دارند و در صورت نیاز، تبدیل به‌صورت صریح انجام شود.

تبدیل میان Number و BigInt

می‌توان Number و BigInt را به‌صورت صریح به یکدیگر تبدیل کرد:

const value = 100n;

const numberValue = Number(value);

یا:

const value = 100;

const bigIntValue = BigInt(value);

اما این تبدیل‌ها همیشه بدون ریسک نیستند.

مهم‌ترین مورد، تبدیل BigInt بزرگ به Number است. اگر مقدار خارج از محدوده Safe Integer باشد، Number ممکن است نتواند آن را دقیق نگه دارد.

بنابراین:

Large BigInt
↓
Number()
↓
Possible Precision Loss

به همین دلیل، تبدیل BigInt به Number باید زمانی انجام شود که محدودیت دقت Number برای آن مقدار قابل قبول باشد.

از طرف دیگر، اگر یک Number بزرگ پیش از تبدیل دقت خود را از دست داده باشد، تبدیل آن به BigInt مقدار اصلی را برنمی‌گرداند.

پس تبدیل Type، یک عملیات صرفاً نحوی نیست؛ ممکن است روی دقت Value تأثیر بگذارد.

مقایسه Number و BigInt

Number و BigInt حتی زمانی که مقدار عددی یکسانی دارند، از نظر Type متفاوت هستند.

برای مثال:

10n === 10;

نتیجه:

false

زیرا === هم مقدار و هم Type را در نظر می‌گیرد.

در اینجا:

10  → Number
10n → BigInt

اما مقایسه با == رفتار متفاوتی دارد:

10n == 10;

نتیجه:

true

بنابراین هنگام کار با Number و BigInt، باید مشخص باشد که آیا مقایسه صرفاً بر اساس مقدار انجام می‌شود یا Type نیز باید یکسان باشد.

در کدهای Type-sensitive، استفاده آگاهانه از === معمولاً رفتار واضح‌تری ایجاد می‌کند.

BigInt در چه شرایطی انتخاب مناسبی است؟

اکنون مسئله اصلی فصل روشن شده است.

Number برای بیشتر محاسبات معمولی مناسب است. مشکل زمانی ایجاد می‌شود که با Integer بزرگی مواجه باشیم که باید بدون از دست رفتن دقت نگهداری یا محاسبه شود.

برای مثال، تصور کنید Application یک شمارنده بسیار بزرگ برای تعداد عملیات پردازش‌شده نگهداری می‌کند:

const processedItems = 9007199254740993n;

در چنین شرایطی BigInt می‌تواند انتخاب مناسبی باشد، زیرا مقدار یک Integer است و دقت آن اهمیت دارد.

مواردی مانند:

Integerهای بسیار بزرگ
شمارنده‌های بزرگ
محاسبات دقیق Integer
داده‌های عددی بزرگ که باید مقدارشان دقیق باقی بماند

می‌توانند از BigInt استفاده کنند.

در مقابل، برای مقدارهایی مانند:

const price = 1200;
const quantity = 5;

استفاده از BigInt مزیت خاصی ایجاد نمی‌کند.

همچنین BigInt برای مقدارهای اعشاری طراحی نشده است:

12.5
3.14
99.99

بنابراین انتخاب میان Number و BigInt نباید بر اساس این تصور باشد که یکی «بهتر» از دیگری است.

مدل ذهنی صحیح این است:

Number
→ General Numeric Values

BigInt
→ Large Integer Values

هر کدام برای مسئله متفاوتی طراحی شده‌اند.

Best Practices
برای Integerهای معمولی از Number استفاده کنید

اگر مقدار در محدوده Safe Integer قرار دارد و نیاز خاصی به BigInt وجود ندارد، Number انتخاب طبیعی است.

برای Integerهای بزرگ و دقیق از BigInt استفاده کنید

اگر مقدار ممکن است از محدوده Safe Integer عبور کند و دقت آن اهمیت داشته باشد، BigInt را در نظر بگیرید.

برای BigInt Literal از n استفاده کنید
const id = 9007199254740993n;

این شکل، Type مقدار را به‌صورت واضح نشان می‌دهد.

Number و BigInt را بدون تصمیم آگاهانه ترکیب نکنید

عملیات حسابی مستقیم میان این دو Type مجاز نیست:

10 + 20n;

اگر تبدیل لازم است، آن را به‌صورت صریح انجام دهید.

تبدیل BigInt به Number را با توجه به Precision انجام دهید

اگر BigInt بزرگ باشد، تبدیل به Number می‌تواند باعث از دست رفتن دقت شود.

BigInt را برای Decimal انتخاب نکنید

BigInt برای Integer است و نتیجه‌های اعشاری را نگهداری نمی‌کند.

اشتباهات رایج
تصور اینکه Number تمام Integerها را دقیق نمایش می‌دهد

Number محدوده‌ای برای نمایش دقیق Integerها دارد. برای بررسی آن می‌توان از Number.isSafeInteger() استفاده کرد.

تصور اینکه BigInt نسخه بهتر Number است

BigInt جایگزین عمومی Number نیست. این Type برای مسئله مشخصی یعنی Integerهای بزرگ و دقیق طراحی شده است.

فراموش کردن n
const value = 100;

یک Number است.

اما:

const value = 100n;

یک BigInt است.

ترکیب مستقیم Number و BigInt
10 + 20n;

باعث TypeError می‌شود.

انتظار داشتن مقدار اعشاری از BigInt
7n / 2n;

نتیجه:

3n

است، نه 3.5.

انتظار بازیابی Precision با تبدیل Number به BigInt

اگر Number پیش از تبدیل مقدار دقیق خود را از دست داده باشد، BigInt() نمی‌تواند مقدار اصلی را بازیابی کند.

Summary

Number برای بیشتر محاسبات عددی JavaScript مناسب است، اما نمی‌تواند تمام Integerها را با دقت کامل نمایش دهد.

محدوده مهم برای Integerهای دقیق با Safe Integer مشخص می‌شود و بزرگ‌ترین مقدار آن:

Number.MAX_SAFE_INTEGER;

است که برابر با:

9007199254740991

است.

وقتی Application به Integer بزرگ‌تری نیاز دارد و دقت مقدار اهمیت دارد، BigInt راه‌حل JavaScript است.

یک BigInt Literal با n مشخص می‌شود:

const value = 9007199254740993n;

BigInt می‌تواند عملیات حسابی Integer را انجام دهد، اما نمی‌توان آن را مستقیماً در عملیات حسابی با Number ترکیب کرد.

بنابراین انتخاب میان Number و BigInt باید بر اساس نوع داده و نیاز مسئله انجام شود، نه صرفاً بزرگی عدد.

زیرا Number نمی‌تواند تمام Integerهای بزرگ را به‌صورت دقیق و متمایز نمایش دهد. BigInt این مسئله را با پشتیبانی از Integerهای با دقت دلخواه حل می‌کند.

تفاوت Number و BigInt چیست؟

Number مدل عددی عمومی JavaScript است و می‌تواند Integer و مقدارهای اعشاری را نمایش دهد، اما دقت Integer آن محدود است. BigInt برای Integerهای بزرگ با دقت دلخواه طراحی شده و مقدار اعشاری ندارد.

آیا می‌توان Number و BigInt را با هم جمع کرد؟

خیر. عملیات حسابی مستقیم میان Number و BigInt مجاز نیست و باعث TypeError می‌شود. در صورت نیاز باید تبدیل Type به‌صورت صریح انجام شود.

آیا تبدیل Number به BigInt همیشه امن است؟

خیر. اگر Number از محدوده Safe Integer خارج باشد، ممکن است پیش از تبدیل دقت خود را از دست داده باشد و تبدیل به BigInt نمی‌تواند مقدار اصلی را بازیابی کند.

Conclusion

در این فصل از یک مسئله مشخص شروع کردیم: Number برای نمایش دقیق تمام Integerهای بزرگ کافی نیست.

Number برای بیشتر نیازهای عددی Application مناسب است، اما زمانی که یک Integer بزرگ باید بدون از دست رفتن دقت نگهداری یا محاسبه شود، محدودیت Safe Integer اهمیت پیدا می‌کند.

بنابراین BigInt نسخه بهتر Number نیست؛ ابزاری برای مسئله‌ای متفاوت است.

اگر مقدار یک Integer معمولی است، Number انتخاب طبیعی است. اگر مقدار یک Integer بزرگ است و دقت آن اهمیت دارد، BigInt می‌تواند انتخاب مناسب باشد.

در فصل بعد، همین مسیر عددی را ادامه می‌دهیم و به سراغ Date می‌رویم؛ جایی که JavaScript باید زمان را به شکلی قابل پردازش و قابل استفاده در Application نمایش دهد.
