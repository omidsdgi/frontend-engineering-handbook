# Chapter 01

# What is JavaScript?

---

# اهداف فصل

پس از مطالعه این فصل، انتظار می‌رود بتوانید:

- JavaScript را به‌صورت دقیق و مهندسی تعریف کنید.
- تفاوت JavaScript، ECMAScript، JavaScript Engine و Runtime را توضیح دهید.
- مفهوم High-Level، Multi-Paradigm و Object-Oriented را در JavaScript درک کنید.
- جایگاه JavaScript را در دنیای توسعه نرم‌افزار مدرن بشناسید.
- به رایج‌ترین پرسش‌های مصاحبه فنی این مبحث پاسخ دهید.
- مدل ذهنی صحیحی برای ادامه یادگیری JavaScript در فصل‌های بعد به دست آورید.

---

# مقدمه

بیشتر افراد یادگیری JavaScript را با حفظ کردن سینتکس آغاز می‌کنند. آن‌ها با متغیرها، توابع، شرط‌ها و حلقه‌ها آشنا می‌شوند و تصور می‌کنند هرچه تعداد بیشتری از دستورات زبان را بدانند، برنامه‌نویس بهتری خواهند بود.

این روش شاید در کوتاه‌مدت باعث شود چند برنامه ساده نوشته شود، اما در بلندمدت معمولاً به بن‌بست می‌رسد. دلیل این موضوع آن است که JavaScript صرفاً مجموعه‌ای از کلمات کلیدی و قوانین نگارشی نیست؛ بلکه سیستمی است که بر پایه مجموعه‌ای از مفاهیم، استانداردها و مدل‌های اجرایی طراحی شده است. اگر این مفاهیم به‌درستی درک نشوند، بسیاری از رفتارهای زبان عجیب، غیرقابل پیش‌بینی یا حتی اشتباه به نظر خواهند رسید.

هدف این کتاب آموزش دستورات JavaScript نیست؛ هدف آن ساختن یک مدل ذهنی صحیح است. هنگامی که این مدل ذهنی شکل بگیرد، یادگیری قابلیت‌های جدید زبان بسیار ساده‌تر خواهد شد و بسیاری از رفتارهایی که در نگاه اول پیچیده به نظر می‌رسند، کاملاً منطقی خواهند بود.

به همین دلیل، پیش از آنکه وارد مباحثی مانند متغیرها، انواع داده، توابع یا شیءها شویم، ابتدا باید بدانیم دقیقاً با چه زبانی روبه‌رو هستیم.

---

# JavaScript چیست؟

اگر همین سؤال را از افراد مختلف بپرسید، احتمالاً پاسخ‌های متفاوتی خواهید شنید.

برخی خواهند گفت:

> JavaScript زبان برنامه‌نویسی صفحات وب است.

عده‌ای دیگر پاسخ خواهند داد:

> زبانی است که در مرورگر اجرا می‌شود.

بعضی نیز آن را این‌گونه معرفی می‌کنند:

> زبانی برای ایجاد تعامل در صفحات وب.

هیچ‌یک از این پاسخ‌ها کاملاً اشتباه نیستند، اما هیچ‌کدام نیز تصویر کاملی از JavaScript ارائه نمی‌کنند.

تعریفی که یک توسعه‌دهنده حرفه‌ای از JavaScript ارائه می‌دهد، بسیار دقیق‌تر است.

---

## تعریف ساده

JavaScript یک زبان برنامه‌نویسی است که برای ساخت نرم‌افزارهای تعاملی طراحی شده و امروزه در محیط‌های مختلفی مانند مرورگر، سرور، برنامه‌های موبایل و حتی برنامه‌های دسکتاپ اجرا می‌شود.

این تعریف برای شروع مناسب است، اما هنوز بسیاری از ویژگی‌های مهم JavaScript را بیان نمی‌کند.

---

## تعریف فنی

JavaScript یک **زبان برنامه‌نویسی سطح بالا (High-Level)، چندپارادایمی (Multi-Paradigm)، شیءگرا (Object-Oriented)، دارای مدیریت خودکار حافظه (Garbage Collected) و پویا (Dynamic)** است که مشخصات آن توسط استاندارد **ECMAScript** تعریف می‌شود و توسط موتورهای اجرای مختلف در Runtimeهای گوناگون اجرا می‌شود.

هر کلمه در این تعریف معنا و اهمیت خاص خود را دارد.

در ادامه این فصل، تمام این ویژگی‌ها به‌صورت دقیق بررسی خواهند شد.

---

# چرا این تعریف اهمیت دارد؟

فرض کنید تنها این جمله را حفظ کنید:

> JavaScript زبان برنامه‌نویسی صفحات وب است.

این جمله اگرچه از نظر تاریخی تا حدی درست است، اما باعث شکل‌گیری یک مدل ذهنی نادرست می‌شود.

اگر چنین تصوری داشته باشید، احتمالاً در ادامه با پرسش‌هایی روبه‌رو خواهید شد که پاسخ آن‌ها برایتان مبهم خواهد بود.

برای مثال:

- چرا JavaScript روی سرور نیز اجرا می‌شود؟
- Node.js چیست؟
- اگر JavaScript زبان مرورگر است، پس Deno و Bun چه هستند؟
- تفاوت JavaScript با ECMAScript چیست؟
- آیا DOM بخشی از JavaScript است؟
- چرا بعضی قابلیت‌ها در مرورگر وجود دارند اما در Node.js وجود ندارند؟

تمام این پرسش‌ها نشان می‌دهد که تعریف ساده JavaScript برای درک صحیح این زبان کافی نیست.

---

# JavaScript فقط یک زبان نیست

یکی از بزرگ‌ترین اشتباهات برنامه‌نویسان تازه‌کار این است که JavaScript را تنها مجموعه‌ای از سینتکس‌ها می‌بینند.

برای مثال:

```javascript
const user = {
  firstName: "Omid",
  age: 58,
};
```

بسیاری تصور می‌کنند تمام اتفاقی که رخ می‌دهد همین چند خط کد است.

در حالی که این تنها بخش کوچکی از فرآیند اجرای برنامه است.

وقتی چنین کدی نوشته می‌شود، در پشت صحنه اجزای مختلفی با یکدیگر همکاری می‌کنند.

در ساده‌ترین نگاه، چهار مفهوم مستقل وجود دارد:

1. زبان JavaScript
2. استاندارد ECMAScript
3. موتور اجرای JavaScript (JavaScript Engine)
4. محیط اجرا (Runtime)

درک تفاوت این چهار مفهوم یکی از مهم‌ترین اهداف این فصل است؛ زیرا بسیاری از سوءبرداشت‌های رایج دقیقاً از یکسان در نظر گرفتن این مفاهیم ناشی می‌شوند.

در فصل‌های بعد خواهیم دید که بسیاری از قابلیت‌هایی که برنامه‌نویسان به اشتباه جزئی از JavaScript می‌دانند، در واقع متعلق به Runtime هستند و نه خود زبان.

---

# برنامه‌نویسی یعنی حل مسئله

یکی از اشتباهات رایج در آموزش برنامه‌نویسی این است که از همان ابتدا تمرکز بر روی دستورات زبان قرار می‌گیرد.

در نتیجه، دانشجو تصور می‌کند برنامه‌نویسی یعنی حفظ کردن دستورها و سپس کنار هم قرار دادن آن‌ها.

اما حقیقت چیز دیگری است.

برنامه‌نویسی پیش از آنکه نوشتن کد باشد، حل مسئله است.

هر برنامه‌ای که نوشته می‌شود، پاسخی برای یک مسئله واقعی است.

کد تنها وسیله‌ای برای بیان آن پاسخ است.

به همین دلیل، در این کتاب تلاش خواهیم کرد پیش از معرفی هر قابلیت، ابتدا مسئله‌ای را که آن قابلیت برای حل آن ایجاد شده است بررسی کنیم.

این رویکرد باعث می‌شود مطالب به جای حفظ شدن، درک شوند و در پروژه‌های واقعی نیز قابل استفاده باشند.

---پیش از پاسخ دادن به این پرسش، لازم است چند ویژگی مهم JavaScript را بشناسیم؛ ویژگی‌هایی که تقریباً در تمام معرفی‌های رسمی این زبان مشاهده می‌شوند، اما معمولاً بدون توضیح از کنار آن‌ها عبور می‌شود.

تقریباً در تمام مستندات فنی، JavaScript با مجموعه‌ای از صفت‌ها معرفی می‌شود:

- High-Level
- Multi-Paradigm
- Object-Oriented
- Prototype-Based
- Dynamic
- Garbage-Collected

اگر این واژه‌ها را تنها حفظ کنید، در عمل کمکی به درک زبان نخواهند کرد. اما اگر بدانید هر یک دقیقاً چه مفهومی دارند و چرا JavaScript با این ویژگی‌ها شناخته می‌شود، در ادامه مسیر یادگیری بسیاری از رفتارهای این زبان برایتان بدیهی و منطقی خواهد شد.

---

# منظور از High-Level چیست؟

یکی از اولین ویژگی‌هایی که تقریباً در تمام معرفی‌های JavaScript مشاهده می‌شود، عبارت **High-Level Programming Language** است.

اما این اصطلاح دقیقاً چه معنایی دارد؟

برای پاسخ به این سؤال ابتدا باید بدانیم کامپیوتر چگونه برنامه‌ها را اجرا می‌کند.

پردازنده تنها زبان ماشین را متوجه می‌شود؛ زبانی متشکل از صفر و یک که مستقیماً توسط سخت‌افزار اجرا می‌شود.

نمونه‌ای از زبان ماشین ممکن است چیزی شبیه این باشد:

```text
10110000 01100001
10110001 01100010
11000011
```

واضح است که نوشتن برنامه با چنین زبانی برای انسان تقریباً غیرممکن است.

به همین دلیل زبان‌های برنامه‌نویسی به وجود آمدند تا فاصله میان انسان و سخت‌افزار را کاهش دهند.

---

## تعریف High-Level Language

زبان‌های برنامه‌نویسی را معمولاً از نظر میزان نزدیکی به سخت‌افزار به دو گروه کلی تقسیم می‌کنند:

- Low-Level Languages
- High-Level Languages

زبان‌های سطح پایین، کنترل بسیار زیادی روی سخت‌افزار در اختیار برنامه‌نویس قرار می‌دهند، اما نوشتن برنامه با آن‌ها دشوارتر است.

در مقابل، زبان‌های سطح بالا بسیاری از جزئیات پیچیده سخت‌افزار را از دید برنامه‌نویس پنهان می‌کنند و اجازه می‌دهند تمرکز اصلی روی حل مسئله باشد.

به این پنهان‌سازی جزئیات **Abstraction** گفته می‌شود.

در حقیقت، هرچه سطح انتزاع یک زبان بیشتر باشد، برنامه‌نویس کمتر درگیر جزئیات داخلی سیستم خواهد شد.

JavaScript یکی از زبان‌هایی است که سطح انتزاع بسیار بالایی دارد.

---

## منظور از Abstraction چیست؟

فرض کنید قصد دارید با یک خودرو رانندگی کنید.

برای حرکت دادن خودرو لازم نیست بدانید:

- پیستون‌ها چگونه حرکت می‌کنند.
- سیستم احتراق چگونه کار می‌کند.
- سوپاپ‌ها در چه زمانی باز و بسته می‌شوند.
- ECU چگونه موتور را کنترل می‌کند.

تمام این پیچیدگی‌ها پشت یک فرمان، چند پدال و یک دسته‌دنده پنهان شده‌اند.

این دقیقاً همان چیزی است که در علوم کامپیوتر **Abstraction** نامیده می‌شود.

زبان‌های سطح بالا نیز همین کار را انجام می‌دهند.

به جای آنکه برنامه‌نویس مستقیماً با حافظه، ثبات‌های پردازنده یا دستورهای ماشین سروکار داشته باشد، تنها کافی است مفاهیم سطح بالاتری مانند متغیر، تابع یا شیء را به کار ببرد.

---

## JavaScript چه چیزهایی را از ما پنهان می‌کند؟

یکی از مهم‌ترین ویژگی‌های JavaScript این است که بسیاری از عملیات پیچیده را به‌صورت خودکار انجام می‌دهد.

برای مثال، زمانی که یک شیء ایجاد می‌کنید:

```javascript
const user = {
  firstName: "Omid",
  age: 58,
};
```

نیازی نیست بدانید:

- این شیء در کدام بخش حافظه قرار گرفته است.
- چه مقدار حافظه برای آن رزرو شده است.
- چه زمانی باید حافظه آن آزاد شود.
- آدرس حافظه آن چیست.

تمام این عملیات توسط موتور اجرای JavaScript مدیریت می‌شود.

---

## Garbage Collection

یکی از مهم‌ترین قابلیت‌هایی که باعث شده JavaScript یک زبان سطح بالا محسوب شود، **مدیریت خودکار حافظه** است.

در زبان‌هایی مانند C یا ++C برنامه‌نویس باید خودش حافظه را تخصیص دهد و در زمان مناسب آن را آزاد کند.

اگر این کار فراموش شود، برنامه دچار نشت حافظه (Memory Leak) خواهد شد.

اما در JavaScript چنین مسئولیتی بر عهده برنامه‌نویس نیست.

موتور JavaScript به‌طور مداوم اشیایی را که دیگر مورد استفاده قرار نمی‌گیرند شناسایی کرده و حافظه آن‌ها را آزاد می‌کند.

به این فرآیند **Garbage Collection** گفته می‌شود.

وجود چنین قابلیتی یکی از مهم‌ترین دلایل سطح بالای JavaScript است.

---

## آیا High-Level بودن فقط مزیت است؟

خیر.

هر سطح انتزاعی، علاوه بر مزایا، هزینه‌هایی نیز دارد.

از مهم‌ترین مزایای زبان‌های سطح بالا می‌توان به موارد زیر اشاره کرد:

- خوانایی بیشتر
- توسعه سریع‌تر
- کاهش خطاهای مرتبط با حافظه
- نگهداری آسان‌تر پروژه‌ها
- افزایش بهره‌وری برنامه‌نویس

در مقابل، مهم‌ترین محدودیت آن‌ها این است که کنترل مستقیم روی سخت‌افزار کمتر می‌شود و موتور اجرا باید بخشی از عملیات را به‌صورت خودکار انجام دهد.

البته موتورهای مدرن JavaScript مانند V8 با استفاده از تکنیک‌هایی مانند **Just-In-Time Compilation (JIT)** این محدودیت را تا حد زیادی جبران کرده‌اند؛ موضوعی که در فصل JavaScript Engine به‌صورت کامل بررسی خواهیم کرد.

---

## اشتباه رایج

بعضی افراد تصور می‌کنند High-Level بودن یعنی زبان کند است.

این برداشت دقیق نیست.

سطح انتزاع و سرعت اجرا دو مفهوم متفاوت هستند.

سرعت واقعی اجرای یک برنامه علاوه بر خود زبان، به کیفیت موتور اجرا، نحوه پیاده‌سازی الگوریتم و بسیاری عوامل دیگر بستگی دارد.

به همین دلیل، JavaScript با وجود High-Level بودن، امروزه در بسیاری از برنامه‌های بزرگ و پیچیده مورد استفاده قرار می‌گیرد.

## پاسخ کوتاه طلایی مصاحبه

**سؤال**

منظور از High-Level بودن JavaScript چیست؟

**پاسخ**

JavaScript یک زبان سطح بالا است؛ یعنی بسیاری از جزئیات پیچیده سخت‌افزار و مدیریت حافظه را از برنامه‌نویس پنهان می‌کند و اجازه می‌دهد تمرکز اصلی بر حل مسئله باشد، نه مدیریت منابع سیستم.

# Multi-Paradigm یعنی چه؟

یکی دیگر از ویژگی‌هایی که تقریباً در تمام معرفی‌های JavaScript مشاهده می‌شود، عبارت **Multi-Paradigm Programming Language** است.

در نگاه اول، این عبارت ممکن است صرفاً یک اصطلاح تخصصی به نظر برسد؛ اما در واقع یکی از مهم‌ترین ویژگی‌های JavaScript است و بخش بزرگی از انعطاف‌پذیری این زبان از همین قابلیت ناشی می‌شود.

برای درک مفهوم Multi-Paradigm ابتدا باید بدانیم **Paradigm** چیست.

---

## Paradigm چیست؟

واژه Paradigm را می‌توان به «سبک برنامه‌نویسی» یا «روش حل مسئله» ترجمه کرد.

همان‌طور که برای حل یک مسئله ریاضی می‌توان از روش‌های مختلف استفاده کرد، در برنامه‌نویسی نیز می‌توان یک مسئله را با سبک‌های متفاوتی حل کرد.

به بیان ساده، Paradigm مشخص می‌کند که برنامه‌نویس چگونه درباره مسئله فکر کند و ساختار برنامه را چگونه طراحی نماید.

در طول تاریخ برنامه‌نویسی، پارادایم‌های مختلفی معرفی شده‌اند، اما سه پارادایم بیش از سایرین مورد استفاده قرار گرفته‌اند:

- Procedural Programming
- Object-Oriented Programming
- Functional Programming

JavaScript هر سه پارادایم را پشتیبانی می‌کند و به همین دلیل یک زبان **Multi-Paradigm** محسوب می‌شود.

# برنامه‌نویسی رویه‌ای (Procedural Programming)

برنامه‌نویسی رویه‌ای قدیمی‌ترین و ساده‌ترین سبک برنامه‌نویسی است.

در این روش، برنامه به مجموعه‌ای از دستورات و توابع تقسیم می‌شود که به‌ترتیب اجرا می‌شوند.

برای مثال:

```javascript
function calculatePrice(price, tax) {
  return price + price * tax;
}

const total = calculatePrice(100, 0.1);
```

در این مثال، تمرکز برنامه روی اجرای یک تابع است.

در پروژه‌های کوچک، این روش کاملاً مناسب است؛ اما هرچه اندازه پروژه افزایش پیدا کند، مدیریت وابستگی‌ها و نگهداری کد دشوارتر می‌شود.

---

# برنامه‌نویسی شیءگرا (Object-Oriented Programming)

در برنامه‌نویسی شیءگرا، تمرکز از «توابع» به «اشیاء» منتقل می‌شود.

در این روش، داده و رفتار مرتبط با آن داده در کنار یکدیگر قرار می‌گیرند.

برای مثال:

```javascript
const account = {
  owner: "Omid",

  deposit(amount) {
    console.log(`${amount} deposited`);
  },
};
```

در این مثال، شیء account تنها مجموعه‌ای از داده‌ها نیست؛ بلکه رفتار مربوط به آن نیز درون همان شیء قرار گرفته است.

این رویکرد باعث می‌شود پروژه‌های بزرگ ساختار منظم‌تر و قابل نگهداری‌تری داشته باشند.

در فصل‌های آینده، شیءگرایی در JavaScript را به‌صورت کامل بررسی خواهیم کرد.

---

# برنامه‌نویسی تابعی (Functional Programming)

پارادایم سوم، برنامه‌نویسی تابعی است.

در این سبک، تابع به مهم‌ترین عنصر برنامه تبدیل می‌شود.

ویژگی مهم JavaScript این است که توابع در این زبان **First-Class Citizen** هستند.

این یعنی:

- می‌توان تابع را داخل متغیر ذخیره کرد.
- می‌توان تابع را به تابع دیگری ارسال کرد.
- می‌توان تابع را از داخل یک تابع بازگرداند.
- می‌توان توابع را مانند سایر داده‌ها مدیریت کرد.

برای مثال:

```javascript
const greet = function () {
  console.log("Hello");
};

const execute = greet;

execute();
```

وجود چنین قابلیتی باعث شده JavaScript برای برنامه‌نویسی تابعی نیز زبان بسیار مناسبی باشد.

---

# چرا Multi-Paradigm بودن مهم است؟

برخی زبان‌ها تقریباً شما را مجبور می‌کنند از یک سبک مشخص استفاده کنید.

اما JavaScript چنین محدودیتی ندارد.

شما می‌توانید:

- بخش کوچکی از برنامه را به‌صورت رویه‌ای بنویسید.
- قسمت دیگری را با رویکرد شیءگرا طراحی کنید.
- و در بخش‌هایی که مناسب‌تر است، از تکنیک‌های برنامه‌نویسی تابعی استفاده کنید.

این انعطاف‌پذیری یکی از مهم‌ترین دلایل محبوبیت JavaScript است.

---

# اشتباه رایج

گاهی گفته می‌شود:

> JavaScript یک زبان شیءگرا است.

این جمله کامل نیست.

همچنین گفته می‌شود:

> JavaScript یک زبان تابعی است.

این نیز تعریف دقیقی نیست.

تعریف صحیح این است:

> JavaScript یک زبان Multi-Paradigm است که از برنامه‌نویسی رویه‌ای، شیءگرا و تابعی پشتیبانی می‌کند.

همین ویژگی باعث می‌شود توسعه‌دهنده بتواند برای هر مسئله، مناسب‌ترین سبک طراحی را انتخاب کند.

---

# پاسخ کوتاه طلایی مصاحبه

**سؤال**

منظور از Multi-Paradigm بودن JavaScript چیست؟

**پاسخ**

JavaScript محدود به یک سبک برنامه‌نویسی نیست و از چندین پارادایم از جمله Procedural، Object-Oriented و Functional Programming پشتیبانی می‌کند. این ویژگی باعث می‌شود برنامه‌نویس بتواند متناسب با مسئله، بهترین روش طراحی را انتخاب کند.

---

# آیا JavaScript یک زبان Object-Oriented است؟

این سؤال یکی از رایج‌ترین پرسش‌های مصاحبه‌های فنی است و پاسخ آن معمولاً با یک سوءبرداشت همراه است.

بسیاری از برنامه‌نویسان تصور می‌کنند تنها زبان‌هایی مانند Java یا C# شیءگرا هستند؛ زیرا از کلاس‌ها (Class) استفاده می‌کنند.

اما JavaScript سال‌ها پیش از معرفی کلاس‌ها نیز یک زبان شیءگرا بود.

دلیل این موضوع آن است که **شیءگرایی در JavaScript بر پایه Prototype طراحی شده است، نه بر پایه Class.**

کلاس‌هایی که امروزه در JavaScript می‌بینید، از نسخه ES2015 به زبان اضافه شده‌اند، اما در حقیقت یک **لایه نحوی (Syntactic Sugar)** روی همان سیستم Prototype هستند و مدل بنیادی زبان را تغییر نداده‌اند.

در فصل «Objects and Prototypes» این موضوع را با جزئیات کامل بررسی خواهیم کرد.

---

# چرا Jonas Schmedtmann روی Object-Oriented بودن JavaScript تأکید می‌کند؟

یکی از نکاتی که Jonas بارها در دوره خود بر آن تأکید می‌کند این است که:

> اگر مدل شیءگرایی JavaScript را درک نکنید، بخش بزرگی از رفتار این زبان برایتان مبهم باقی خواهد ماند.

دلیل این تأکید روشن است.

بخش بزرگی از قابلیت‌های JavaScript مانند:

- Array
- Function
- Date
- Map
- Set
- Promise

همگی شیء هستند و از سیستم Prototype استفاده می‌کنند.

اگر تصور کنید شیءگرایی در JavaScript فقط به کلاس‌ها محدود می‌شود، درک بسیاری از مفاهیم پیشرفته مانند Prototype Chain، Inheritance و Delegation دشوار خواهد شد.

بنابراین، شیءگرایی در JavaScript یک قابلیت جانبی نیست؛ بلکه بخشی از هویت این زبان است.

در اینجا پرسشی اساسی مطرح می‌شود که پاسخ آن مسیر ادامه این فصل را مشخص خواهد کرد.

اگر JavaScript تنها یک زبان برنامه‌نویسی است، پس اصطلاحاتی مانند **ECMAScript**، **JavaScript Engine** و **Runtime** دقیقاً به چه معنا هستند و هر کدام چه نقشی در اجرای یک برنامه JavaScript ایفا می‌کنند؟
