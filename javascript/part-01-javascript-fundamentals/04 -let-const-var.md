# Chapter 04 — let, const and var

---

# اهداف فصل

پس از پایان این فصل، انتظار می‌رود بتوانید:

- علت وجود سه روش مختلف برای تعریف متغیر در JavaScript را توضیح دهید.
- تفاوت‌های `var`، `let` و `const` را از نظر طراحی زبان درک کنید.
- بدانید چرا امروزه استفاده از `var` در پروژه‌های جدید توصیه نمی‌شود.
- مفهوم Block Scope را در سطح مقدماتی درک کنید.
- بهترین روش تعریف متغیرها را در پروژه‌های واقعی انتخاب کنید.

---

# مقدمه

در فصل قبل یاد گرفتیم که **Variable** محلی برای نگهداری یک مقدار در حافظه است. همچنین دیدیم که هر متغیر ابتدا **تعریف (Declaration)** می‌شود و سپس می‌تواند مقداری را در خود ذخیره کند.

اکنون پرسش مهم‌تری مطرح می‌شود.

اگر هدف همه آن‌ها تعریف یک متغیر است، چرا JavaScript سه روش مختلف برای این کار در اختیار ما قرار داده است؟

```javascript
var user = 'Omid';

let age = 30;

const country = 'Germany';
```

آیا این سه دستور دقیقاً یک کار انجام می‌دهند؟

اگر پاسخ مثبت است، چرا سه کلمه کلیدی مختلف وجود دارد؟

و اگر پاسخ منفی است، تفاوت آن‌ها دقیقاً چیست؟

پاسخ این پرسش‌ها تنها با حفظ کردن تفاوت‌های `var`، `let` و `const` به دست نمی‌آید؛ بلکه ابتدا باید بدانیم این سه کلمه در چه شرایطی به زبان اضافه شده‌اند و هر یک قرار بوده چه مشکلی را حل کنند.

---

# چرا JavaScript از ابتدا فقط `var` داشت؟

در نخستین نسخه JavaScript که در سال 1995 معرفی شد، تنها یک روش برای تعریف متغیر وجود داشت.

آن روش، `var` بود.

```javascript
var firstName = 'Jonas';
```

در آن زمان JavaScript زبانی بسیار کوچک بود و قرار نبود برنامه‌های بزرگ یا پیچیده با آن نوشته شوند.

به همین دلیل، طراحی اولیه زبان نیز بسیار ساده بود.

اما با گسترش JavaScript، برنامه‌ها بزرگ‌تر شدند و توسعه‌دهندگان با مشکلاتی روبه‌رو شدند که بخش قابل توجهی از آن‌ها به رفتار `var` بازمی‌گشت.

---

# مشکل اصلی `var`

بزرگ‌ترین ایراد `var` این نبود که کد را طولانی‌تر می‌کند یا خوانایی کمتری دارد.

مشکل اصلی این بود که رفتار آن در برخی شرایط با انتظار برنامه‌نویسان سازگار نبود.

به عنوان مثال، امکان تعریف مجدد یک متغیر با استفاده از `var` وجود دارد.

```javascript
var username = 'Ali';

var username = 'Sara';
```

این کد بدون هیچ خطایی اجرا می‌شود.

در پروژه‌های کوچک شاید این موضوع اهمیت چندانی نداشته باشد، اما در پروژه‌هایی که هزاران خط کد دارند، تعریف دوباره یک متغیر می‌تواند باعث ایجاد خطاهایی شود که پیدا کردن آن‌ها بسیار دشوار است.

این تنها یکی از مشکلات `var` بود.

در فصل‌های آینده با مفاهیمی مانند **Hoisting** و **Function Scope** آشنا خواهیم شد و خواهیم دید که بسیاری از رفتارهای عجیب JavaScript به استفاده از `var` مربوط می‌شوند.

در این مرحله تنها کافی است بدانیم که با رشد JavaScript، مشخص شد طراحی اولیه `var` دیگر پاسخگوی نیاز پروژه‌های مدرن نیست.

---

# ورود ES6 و آغاز نسل جدید متغیرها

در سال 2015 نسخه‌ای از استاندارد ECMAScript منتشر شد که تحول بزرگی در JavaScript ایجاد کرد.

این نسخه که با نام **ES6** یا **ECMAScript 2015** شناخته می‌شود، قابلیت‌های متعددی را به زبان اضافه کرد.

یکی از مهم‌ترین این قابلیت‌ها، معرفی دو کلمه کلیدی جدید بود:

- `let`
- `const`

هدف از اضافه شدن این دو کلمه کلیدی، حذف `var` نبود.

بلکه هدف، برطرف کردن مشکلات طراحی اولیه و ارائه روشی امن‌تر برای مدیریت متغیرها بود.

از این نسخه به بعد، برنامه‌نویسان می‌توانستند بسته به نوع داده و نیاز پروژه، روش مناسب تعریف متغیر را انتخاب کنند.

---

# نکته مهندسی

وجود سه روش برای تعریف متغیر به این معنا نیست که هر سه به یک اندازه در پروژه‌های مدرن استفاده می‌شوند.

امروزه در اکثر پروژه‌های حرفه‌ای، استفاده از `let` و `const` به استاندارد رایج تبدیل شده است و استفاده از `var` تنها در کدهای قدیمی یا هنگام بررسی رفتار تاریخی JavaScript دیده می‌شود.

به همین دلیل، در ادامه این فصل ابتدا `let` و `const` را بررسی می‌کنیم و سپس به این پرسش پاسخ خواهیم داد که در چه شرایطی ممکن است هنوز با `var` روبه‌رو شویم.
---

# آشنایی با `let`

همان‌طور که در بخش قبل دیدیم، یکی از اهداف اصلی استاندارد ES2015، رفع محدودیت‌ها و مشکلات طراحی اولیه JavaScript بود. در همین راستا، کلمه کلیدی **`let`** به زبان اضافه شد.

در نگاه اول، `let` نیز مانند `var` برای تعریف متغیر استفاده می‌شود.

```javascript
let firstName = 'Omid';
```

اما تفاوت‌های مهمی میان این دو وجود دارد که باعث شده امروزه `let` جایگزین اصلی `var` در توسعه نرم‌افزارهای مدرن باشد.

---

# ویژگی اول: امکان تغییر مقدار

متغیری که با `let` تعریف می‌شود، می‌تواند در طول اجرای برنامه مقدار جدیدی دریافت کند.

```javascript
let score = 10;

score = 20;

console.log(score);
```

خروجی:

```text
20
```

این ویژگی باعث می‌شود `let` برای داده‌هایی مناسب باشد که انتظار داریم مقدار آن‌ها در طول اجرای برنامه تغییر کند.

برای مثال:

- تعداد کالاهای سبد خرید
- موقعیت اسکرول صفحه
- وضعیت ورود کاربر
- شمارنده‌ها
- نتایج محاسبات

در تمام این موارد، مقدار متغیر ممکن است بارها تغییر کند.

---

# ویژگی دوم: عدم امکان تعریف مجدد

برخلاف `var`، متغیری که با `let` تعریف شده باشد، در همان محدوده (Scope) دوباره قابل تعریف نیست.

```javascript
let username = 'Ali';

let username = 'Sara';
```

نتیجه:

```text
SyntaxError
```

این رفتار یکی از مهم‌ترین مزایای `let` است.

در پروژه‌های بزرگ، تعریف مجدد یک متغیر معمولاً ناشی از خطای برنامه‌نویس است. جلوگیری از این خطا باعث می‌شود بسیاری از اشکالات برنامه در همان زمان توسعه شناسایی شوند.

---

# Block Scope چیست؟

مهم‌ترین تفاوت `let` و `var` در مفهوم **Block Scope** است.

اما Block دقیقاً چیست؟

در JavaScript، هر بخشی از کد که میان آکولاد (`{}`) قرار می‌گیرد، یک **Block** محسوب می‌شود.

برای مثال:

```javascript
if (true) {

}
```

یا

```javascript
for (let i = 0; i < 5; i++) {

}
```

یا

```javascript
{
    console.log('Hello');
}
```

همه این قسمت‌ها یک Block هستند.

متغیری که با `let` تعریف می‌شود، تنها در همان Block قابل دسترسی است.

---

## مثال

```javascript
if (true) {

  let message = 'Hello';

  console.log(message);

}

console.log(message);
```

نتیجه:

```text
ReferenceError
```

چرا؟

زیرا متغیر `message` فقط داخل همان Block وجود دارد و پس از پایان Block از بین می‌رود.

---

# چرا Block Scope اهمیت دارد؟

فرض کنید در یک پروژه بزرگ صدها فایل و هزاران متغیر وجود دارد.

اگر همه متغیرها در تمام برنامه قابل دسترسی باشند، احتمال تداخل نام‌ها بسیار زیاد خواهد شد.

اما Block Scope باعث می‌شود هر متغیر فقط در محدوده‌ای که واقعاً به آن نیاز داریم وجود داشته باشد.

در نتیجه:

- احتمال خطا کاهش پیدا می‌کند.
- خوانایی کد افزایش می‌یابد.
- نگهداری پروژه ساده‌تر می‌شود.
- اشکال‌زدایی آسان‌تر خواهد شد.

به همین دلیل Block Scope یکی از مهم‌ترین تغییرات JavaScript مدرن محسوب می‌شود.

---

# معرفی اولیه Scope

در این فصل چندین بار از واژه **Scope** استفاده کردیم.

در حال حاضر تنها کافی است Scope را این‌گونه تعریف کنیم:

> Scope محدوده‌ای از برنامه است که یک متغیر در آن قابل مشاهده و قابل استفاده است.

در فصل مستقلی با عنوان **Scope and Scope Chain** این مفهوم را به‌صورت کامل بررسی خواهیم کرد.

در اینجا تنها هدف ما درک تفاوت رفتار `let` و `var` است.

او معتقد است استفاده از `let` و `const` باعث می‌شود بسیاری از خطاهای رایج JavaScript پیش از اجرای برنامه شناسایی شوند و کدها قابل پیش‌بینی‌تر باشند.

# اشتباه رایج

گاهی تصور می‌شود:

> `let` نسخه جدید `var` است.

این برداشت دقیق نیست.

`let` صرفاً جایگزین `var` نیست؛ بلکه رفتار متفاوتی دارد و برای رفع بخشی از مشکلات طراحی اولیه زبان معرفی شده است.

# نکات مهم

- `let` برای تعریف متغیرهایی استفاده می‌شود که مقدار آن‌ها ممکن است تغییر کند.
- مقدار متغیرهای `let` قابل تغییر است.
- تعریف مجدد یک متغیر با `let` در یک Scope مجاز نیست.
- متغیرهای `let` دارای **Block Scope** هستند.
- در پروژه‌های مدرن، `let` جایگزین اصلی `var` محسوب می‌شود.

---

# آشنایی با `const`

در بخش قبل یاد گرفتیم که `let` برای متغیرهایی مناسب است که مقدار آن‌ها در طول اجرای برنامه تغییر می‌کند.

اما در بسیاری از موارد، از همان ابتدای برنامه می‌دانیم که مقدار یک متغیر نباید تغییر کند.

برای مثال:

- مقدار π
- نام کشور
- شناسه کاربر
- تنظیمات برنامه
- آدرس API

در چنین شرایطی، JavaScript ابزار مناسب‌تری در اختیار ما قرار می‌دهد:

```javascript
const
```

---

# `const` چیست؟

کلمه کلیدی `const` نیز مانند `let` برای تعریف متغیر استفاده می‌شود، اما یک تفاوت اساسی دارد.

متغیری که با `const` تعریف می‌شود، پس از مقداردهی اولیه دیگر نمی‌تواند به مقدار دیگری اشاره کند.

```javascript
const country = 'Germany';

console.log(country);
```

خروجی:

```text
Germany
```

اگر بعداً تلاش کنیم مقدار جدیدی به آن اختصاص دهیم:

```javascript
const country = 'Germany';

country = 'France';
```

نتیجه:

```text
TypeError
```

---

# Immutable Binding

بسیاری از برنامه‌نویسان تصور می‌کنند `const` یعنی مقدار متغیر غیرقابل تغییر است.

این برداشت دقیق نیست.

آنچه `const` ثابت نگه می‌دارد **Binding** یا **ارجاع متغیر** است، نه لزوماً خود داده.

به همین دلیل، برخی منابع از عبارت **Immutable Binding** استفاده می‌کنند.

به بیان ساده:

> متغیر همیشه باید به همان مقدار اولیه اشاره کند.

---

# آیا `const` همیشه غیرقابل تغییر است؟

پاسخ به نوع داده بستگی دارد.

اگر مقدار یک داده اولیه (Primitive) باشد، عملاً تغییر آن امکان‌پذیر نیست.

```javascript
const age = 25;

age = 30;
```

نتیجه:

```text
TypeError
```

اما اگر مقدار یک شیء باشد، وضعیت متفاوت است.

```javascript
const user = {
  name: 'Omid',
};

user.name = 'Jonas';
```

این کد بدون هیچ خطایی اجرا می‌شود.

چرا؟

زیرا شیء تغییر نکرده است.

آنچه تغییر کرده، یکی از ویژگی‌های داخلی شیء است.

متغیر `user` همچنان به همان شیء اولیه اشاره می‌کند.

---

# یک مدل ذهنی صحیح

فرض کنید متغیر مانند یک برچسب است.

```text
user
  │
  ▼
Object
```

وقتی می‌گوییم:

```javascript
const user = {};
```

برچسب `user` برای همیشه به همین شیء متصل می‌شود.

اما محتویات داخل آن شیء می‌تواند تغییر کند.

در نتیجه:

```javascript
user.name = 'Ali';
```

مجاز است.

اما:

```javascript
user = {};
```

غیرمجاز است.

زیرا در این حالت برچسب قرار است به شیء جدیدی متصل شود.

---

# آیا همیشه باید از `const` استفاده کنیم؟

یکی از توصیه‌های مهم Jonas Schmedtmann این است که:

> همیشه کار را با `const` آغاز کنید.

اگر بعداً متوجه شدید که مقدار متغیر باید تغییر کند، آن را به `let` تبدیل کنید.

این روش چند مزیت مهم دارد:

- احتمال تغییر ناخواسته متغیر کاهش پیدا می‌کند.
- خوانایی کد بیشتر می‌شود.
- برنامه‌نویس از همان ابتدا هدف متغیر را مشخص می‌کند.
- بسیاری از خطاها در زمان توسعه شناسایی می‌شوند.

امروزه این روش به یکی از رایج‌ترین استانداردهای برنامه‌نویسی JavaScript تبدیل شده است.

---

# `var` امروز چه جایگاهی دارد؟

اکنون که با `let` و `const` آشنا شدیم، می‌توانیم جایگاه `var` را بهتر درک کنیم.

در پروژه‌های مدرن تقریباً هیچ دلیلی برای استفاده از `var` وجود ندارد.

دلیل این موضوع، قدیمی بودن `var` نیست.

بلکه رفتار آن در مقایسه با `let` و `const` کمتر قابل پیش‌بینی است.

به همین دلیل، در اکثر راهنماهای سبک کدنویسی (Style Guides) توصیه می‌شود:

- برای مقادیر ثابت از `const`
- برای مقادیر قابل تغییر از `let`
- و از `var` تنها هنگام مطالعه کدهای قدیمی یا بررسی رفتار تاریخی JavaScript استفاده شود.

---

# چه زمانی از `let` و چه زمانی از `const` استفاده کنیم؟

قاعده‌ای ساده وجود دارد.

اگر مقدار متغیر قرار نیست تغییر کند:

```javascript
const apiURL = 'https://api.example.com';
```

اگر احتمال تغییر مقدار وجود دارد:

```javascript
let counter = 0;

counter++;
```

همین قانون ساده، در بخش بزرگی از پروژه‌های JavaScript قابل استفاده است.

❌ `var` دیگر در JavaScript وجود ندارد.

- `const` نیز مانند `let` دارای **Block Scope** است.
- متغیرهای `const` باید هنگام تعریف مقداردهی شوند.
- ارجاع یک متغیر `const` تغییر نمی‌کند.
- ویژگی‌های داخلی یک Object یا عناصر یک Array همچنان می‌توانند تغییر کنند.
- در پروژه‌های مدرن، `const` انتخاب اول برای تعریف متغیرها است.
- تنها زمانی از `let` استفاده کنید که تغییر مقدار متغیر بخشی از منطق برنامه باشد.

# خلاصه فصل

در این فصل با یکی از مهم‌ترین تغییرات JavaScript مدرن آشنا شدیم.

در نسخه‌های اولیه این زبان، تنها روش تعریف متغیرها استفاده از `var` بود. با بزرگ‌تر شدن پروژه‌ها، مشخص شد که رفتار `var` در بسیاری از شرایط باعث کاهش خوانایی کد و افزایش احتمال بروز خطا می‌شود.

به همین دلیل، در استاندارد **ECMAScript 2015 (ES6)** دو کلمه کلیدی جدید، یعنی `let` و `const` معرفی شدند.

در ادامه دیدیم که:

- `let` برای متغیرهایی مناسب است که مقدار آن‌ها در طول اجرای برنامه تغییر می‌کند.
- `const` برای مقادیری مناسب است که نباید به مقدار دیگری تخصیص داده شوند.
- هر دو دارای **Block Scope** هستند و نسبت به `var` رفتار قابل پیش‌بینی‌تری دارند.

در پایان نیز با یکی از مهم‌ترین توصیه‌های توسعه‌دهندگان حرفه‌ای آشنا شدیم:

> **تا زمانی که مجبور نشده‌اید، از `const` استفاده کنید.**

# Key Takeaways

در پایان این فصل باید بتوانید نکات زیر را به‌صورت دقیق توضیح دهید:

- `var` روش قدیمی تعریف متغیر در JavaScript است.
- `let` برای متغیرهای قابل تغییر استفاده می‌شود.
- `const` برای متغیرهایی است که نباید به مقدار دیگری اشاره کنند.
- `let` و `const` دارای **Block Scope** هستند.
- `const` مقدار شیء را ثابت نمی‌کند؛ بلکه ارجاع (Binding) متغیر را ثابت نگه می‌دارد.
- استفاده از `const` باعث خوانایی بیشتر و کاهش خطاهای برنامه می‌شود.
- در پروژه‌های مدرن، استفاده از `var` توصیه نمی‌شود.

# Golden Answers

## تفاوت `var`، `let` و `const`

`var` روش قدیمی تعریف متغیر است.  
`let` برای متغیرهای قابل تغییر استفاده می‌شود.  
`const` برای متغیرهایی است که نباید به مقدار دیگری تخصیص داده شوند.

---

## Block Scope چیست؟

Block Scope محدوده‌ای از برنامه است که با آکولاد (`{}`) مشخص می‌شود و متغیرهای تعریف‌شده با `let` و `const` فقط در همان محدوده قابل دسترسی هستند.

---

## آیا `const` مقدار را ثابت می‌کند؟

خیر.

`const` مقدار را ثابت نمی‌کند؛ بلکه ارجاع متغیر را ثابت نگه می‌دارد.

---

## Immutable Binding یعنی چه؟

یعنی متغیر پس از مقداردهی اولیه، همیشه به همان مقدار یا همان شیء اشاره می‌کند و نمی‌تواند به مقدار دیگری تخصیص داده شود.

---

## چرا استفاده از `const` توصیه می‌شود؟

زیرا:

- خوانایی کد را افزایش می‌دهد.
- احتمال تغییر ناخواسته متغیر را کاهش می‌دهد.
- خطاهای منطقی را زودتر آشکار می‌کند.
- هدف برنامه‌نویس را به‌وضوح نشان می‌دهد.

---

# جمع‌بندی فصل

متغیرها نقطه شروع تقریباً تمام برنامه‌های JavaScript هستند، اما انتخاب روش مناسب برای تعریف آن‌ها نیز به همان اندازه اهمیت دارد.

در این فصل آموختیم که سه کلمه کلیدی `var`، `let` و `const` اگرچه همگی برای تعریف متغیر استفاده می‌شوند، اما فلسفه طراحی و رفتار متفاوتی دارند. شناخت این تفاوت‌ها باعث می‌شود کدهایی بنویسیم که خواناتر، قابل پیش‌بینی‌تر و نگهداری آن‌ها آسان‌تر باشد.

از این فصل به بعد، در تمام مثال‌های کتاب از همان استانداردی استفاده خواهیم کرد که امروزه در اکثر پروژه‌های حرفه‌ای JavaScript رایج است؛ یعنی:

- **`const` انتخاب اول**
- **`let` در صورت نیاز به تغییر مقدار**
- **پرهیز از `var` مگر برای بررسی رفتار تاریخی زبان**

در فصل بعد، با **Operatorها** آشنا خواهیم شد و خواهیم دید که JavaScript چگونه با استفاده از عملگرهای مختلف، مقادیر را محاسبه، مقایسه و پردازش می‌کند.
