# مقدمه

در فصل قبل یاد گرفتیم که **Variable** محلی برای نگهداری یک مقدار در برنامه است. همچنین دیدیم که هر Variable ابتدا **تعریف (Declaration)** می‌شود و سپس می‌تواند مقداری را در خود ذخیره کند.

اکنون پرسش مهم‌تری مطرح می‌شود.

اگر هدف همه آن‌ها تعریف یک Variable است، چرا JavaScript سه روش مختلف برای این کار در اختیار ما قرار داده است؟

```javascript
var user = 'Omid';

let age = 30;

const country = 'Germany';
```

آیا این سه دستور دقیقاً یک کار انجام می‌دهند؟

اگر پاسخ مثبت است، چرا سه کلمه کلیدی مختلف وجود دارد؟

و اگر پاسخ منفی است، تفاوت آن‌ها دقیقاً چیست؟

پاسخ این پرسش‌ها تنها با حفظ کردن تفاوت‌های `var`، `let` و `const` به دست نمی‌آید؛ بلکه ابتدا باید بدانیم این سه کلمه در چه شرایطی به زبان اضافه شده‌اند و هر یک قرار بوده چه مشکلی را حل کنند.

---

# چرا JavaScript از ابتدا فقط `var` داشت؟

در نخستین نسخه JavaScript که در سال 1995 معرفی شد، تنها یک روش برای تعریف Variable وجود داشت.

آن روش، `var` بود.

```javascript
var firstName = 'Jonas';
```

در آن زمان JavaScript زبانی بسیار کوچک بود و قرار نبود برنامه‌های بزرگ یا پیچیده با آن نوشته شوند.

به همین دلیل، طراحی اولیه زبان نیز بسیار ساده بود.

اما با گسترش JavaScript، برنامه‌ها بزرگ‌تر شدند و توسعه‌دهندگان با مشکلاتی روبه‌رو شدند که بخش قابل توجهی از آن‌ها به رفتار `var` بازمی‌گشت.

---

# مشکل اصلی `var`

بزرگ‌ترین ایراد `var` این نبود که کد را طولانی‌تر می‌کند یا خوانایی کمتری دارد.

مشکل اصلی این بود که رفتار آن در برخی شرایط با انتظار برنامه‌نویسان سازگار نبود.

به عنوان مثال، امکان تعریف مجدد یک Variable با استفاده از `var` وجود دارد.

```javascript
var username = 'Ali';

var username = 'Sara';
```

این کد بدون خطای Syntax اجرا می‌شود.

در پروژه‌های کوچک شاید این موضوع اهمیت چندانی نداشته باشد، اما در پروژه‌هایی که هزاران خط کد دارند، تعریف دوباره یک Variable می‌تواند باعث ایجاد خطاهایی شود که پیدا کردن آن‌ها دشوار است.

این تنها یکی از مشکلات `var` بود.

در فصل‌های آینده با مفاهیمی مانند **Hoisting** و **Function Scope** آشنا خواهیم شد و خواهیم دید که بسیاری از رفتارهای `var` با نحوه ایجاد و دسترسی به Bindingها در زمان اجرا ارتباط دارند.

در این مرحله تنها کافی است بدانیم که با رشد JavaScript، مشخص شد طراحی اولیه `var` دیگر پاسخگوی نیاز پروژه‌های مدرن نیست.

---

# ورود ES6 و آغاز نسل جدید متغیرها

در سال 2015 نسخه‌ای از استاندارد ECMAScript منتشر شد که تحول بزرگی در JavaScript ایجاد کرد.

این نسخه که با نام **ES6** یا **ECMAScript 2015** شناخته می‌شود، قابلیت‌های متعددی را به زبان اضافه کرد.

یکی از مهم‌ترین این قابلیت‌ها، معرفی دو کلمه کلیدی جدید بود:

- `let`
- `const`

هدف از اضافه شدن این دو کلمه کلیدی، حذف `var` نبود.

بلکه هدف، برطرف کردن بخشی از مشکلات طراحی اولیه و ارائه روش‌های دقیق‌تر برای مدیریت Variableها بود.

از این نسخه به بعد، برنامه‌نویسان می‌توانستند بسته به نوع داده و نیاز برنامه، روش مناسب تعریف Variable را انتخاب کنند.

---

# نکته مهندسی

وجود سه روش برای تعریف Variable به این معنا نیست که هر سه به یک اندازه در پروژه‌های مدرن استفاده می‌شوند.

امروزه در اکثر پروژه‌های حرفه‌ای، استفاده از `let` و `const` به استاندارد رایج تبدیل شده است و استفاده از `var` بیشتر در کدهای قدیمی یا هنگام بررسی رفتار تاریخی JavaScript دیده می‌شود.

به همین دلیل، در ادامه این فصل ابتدا `let` و `const` را بررسی می‌کنیم و سپس به این پرسش پاسخ خواهیم داد که در چه شرایطی ممکن است هنوز با `var` روبه‌رو شویم.

---

# آشنایی با `let`

همان‌طور که در بخش قبل دیدیم، یکی از اهداف اصلی استاندارد ES2015، رفع محدودیت‌ها و مشکلات طراحی اولیه JavaScript بود. در همین راستا، کلمه کلیدی **`let`** به زبان اضافه شد.

در نگاه اول، `let` نیز مانند `var` برای تعریف Variable استفاده می‌شود.

```javascript
let firstName = 'Omid';
```

اما تفاوت‌های مهمی میان این دو وجود دارد که باعث شده امروزه `let` جایگزین اصلی `var` در توسعه نرم‌افزارهای مدرن باشد.

---

# ویژگی اول: امکان تغییر مقدار

متغیری که با `let` تعریف می‌شود، می‌تواند در طول اجرای برنامه مقدار جدیدی دریافت کند.

```javascript
let score = 10;

score = 20;

console.log(score);
```

خروجی:

```text
20
```

این ویژگی باعث می‌شود `let` برای داده‌هایی مناسب باشد که انتظار داریم مقدار آن‌ها در طول اجرای برنامه تغییر کند.

برای مثال:

- تعداد کالاهای سبد خرید
- موقعیت اسکرول صفحه
- وضعیت ورود کاربر
- شمارنده‌ها
- نتایج محاسبات

در تمام این موارد، مقدار Variable ممکن است در طول اجرای برنامه تغییر کند.

---

# ویژگی دوم: عدم امکان تعریف مجدد

برخلاف `var`، Variableای که با `let` تعریف شده باشد، در همان Scope دوباره قابل تعریف نیست.

```javascript
let username = 'Ali';

let username = 'Sara';
```

نتیجه:

```text
SyntaxError
```

این رفتار یکی از مهم‌ترین مزایای `let` است.

در پروژه‌های بزرگ، تعریف مجدد یک Variable معمولاً ناشی از خطای برنامه‌نویس است. جلوگیری از این خطا باعث می‌شود بسیاری از اشکالات برنامه در همان زمان توسعه شناسایی شوند.

---

# Block Scope چیست؟

مهم‌ترین تفاوت `let` و `var` در مفهوم **Block Scope** است.

اما Block دقیقاً چیست؟

در JavaScript، هر بخشی از کد که میان آکولاد (`{}`) قرار می‌گیرد، یک **Block** محسوب می‌شود.

برای مثال:

```javascript
if (true) {

}
```

یا:

```javascript
for (let i = 0; i < 5; i++) {

}
```

یا:

```javascript
{
  console.log('Hello');
}
```

همه این قسمت‌ها یک Block هستند.

Variableای که با `let` تعریف می‌شود، در محدوده همان Block قابل دسترسی است.

---

## مثال

```javascript
if (true) {

  let message = 'Hello';

  console.log(message);

}

console.log(message);
```

نتیجه:

```text
ReferenceError
```

چرا؟

زیرا Binding مربوط به `message` در Block مربوط به `if` ایجاد شده و خارج از آن Block در دسترس نیست.

در فصل **Scope** این مفهوم به‌صورت کامل‌تر بررسی خواهد شد.

---

# چرا Block Scope اهمیت دارد؟

فرض کنید در یک پروژه بزرگ صدها فایل و هزاران Variable وجود دارد.

اگر محدوده دسترسی Variableها بیش از نیاز واقعی آن‌ها باشد، احتمال تداخل نام‌ها و دسترسی ناخواسته افزایش پیدا می‌کند.

اما Block Scope باعث می‌شود هر Variable فقط در محدوده‌ای که واقعاً به آن نیاز داریم قابل دسترسی باشد.

در نتیجه:

- احتمال خطا کاهش پیدا می‌کند.
- خوانایی کد افزایش می‌یابد.
- نگهداری پروژه ساده‌تر می‌شود.
- اشکال‌زدایی آسان‌تر خواهد شد.

به همین دلیل Block Scope یکی از مهم‌ترین ویژگی‌های JavaScript مدرن محسوب می‌شود.

---

# معرفی اولیه Scope

در این فصل چندین بار از واژه **Scope** استفاده کردیم.

در حال حاضر تنها کافی است Scope را این‌گونه تعریف کنیم:

> Scope محدوده‌ای از برنامه است که یک Variable یا Identifier در آن قابل دسترسی است.

در فصل مستقلی با عنوان **Scope** این مفهوم را به‌صورت کامل بررسی خواهیم کرد.

در اینجا تنها هدف ما درک تفاوت رفتار `let` و `var` است.

`let` صرفاً جایگزین `var` نیست؛ بلکه رفتار متفاوتی دارد و برای رفع بخشی از مشکلات طراحی اولیه زبان معرفی شده است.

# نکات مهم

- `let` برای تعریف Variableهایی استفاده می‌شود که مقدار آن‌ها ممکن است تغییر کند.
- مقدار Variableهای `let` قابل تغییر است.
- تعریف مجدد یک Variable با `let` در یک Scope مجاز نیست.
- Variableهای `let` دارای **Block Scope** هستند.
- در پروژه‌های مدرن، `let` در مواردی استفاده می‌شود که تغییر مقدار ضروری است.

# آشنایی با `const`

در بخش قبل یاد گرفتیم که `let` برای Variableهایی مناسب است که مقدار آن‌ها در طول اجرای برنامه تغییر می‌کند.

اما در بسیاری از موارد، از همان ابتدای برنامه می‌دانیم که یک Variable نباید به مقدار دیگری Assignment شود.

برای مثال:

- مقدار π
- نام کشور
- شناسه کاربر
- تنظیمات برنامه
- آدرس API

در چنین شرایطی، JavaScript ابزار مناسب‌تری در اختیار ما قرار می‌دهد:

```javascript
const
```

---

# `const` چیست؟

کلمه کلیدی `const` نیز مانند `let` برای تعریف Variable استفاده می‌شود، اما یک تفاوت اساسی دارد.

Variableای که با `const` تعریف می‌شود، پس از Initialization نمی‌تواند دوباره به مقدار دیگری Assignment شود.

```javascript
const country = 'Germany';

console.log(country);
```

خروجی:

```text
Germany
```

اگر بعداً تلاش کنیم مقدار جدیدی به آن اختصاص دهیم:

```javascript
const country = 'Germany';

country = 'France';
```

نتیجه:

```text
TypeError
```

---

# Immutable Binding

بسیاری از برنامه‌نویسان تصور می‌کنند `const` یعنی مقدار Variable غیرقابل تغییر است.

این برداشت دقیق نیست.

آنچه `const` ثابت نگه می‌دارد **Binding** است، نه لزوماً خود داده.

به همین دلیل از عبارت **Immutable Binding** استفاده می‌شود.

به بیان ساده:

> Variableای که با `const` تعریف شده، پس از Initialization نمی‌تواند به مقدار دیگری Assignment شود.

---

# آیا `const` همیشه غیرقابل تغییر است؟

پاسخ به نوع Value بستگی دارد.

اگر Value یک Primitive باشد:

```javascript
const age = 25;

age = 30;
```

Assignment مجدد مجاز نیست و نتیجه:

```text
TypeError
```

خواهد بود.

اما اگر Value یک Object باشد، وضعیت متفاوت است.

```javascript
const user = {
  name: 'Omid',
};

user.name = 'Jonas';
```

این کد بدون خطا اجرا می‌شود.

چرا؟

زیرا `user` همچنان به همان Object متصل است.

آنچه تغییر کرده، Property داخل Object است؛ نه Binding مربوط به `user`.

---

# یک مدل ذهنی صحیح

فرض کنید Variable مانند یک برچسب است.

```text
user
  │
  ▼
Object
```

وقتی می‌گوییم:

```javascript
const user = {};
```

Binding مربوط به `user` نمی‌تواند بعداً به Object دیگری Assignment شود.

اما داده داخل همان Object می‌تواند تغییر کند:

```javascript
user.name = 'Ali';
```

در مقابل:

```javascript
user = {};
```

غیرمجاز است.

زیرا در این حالت تلاش می‌کنیم Binding مربوط به `user` را به Object دیگری متصل کنیم.

---

# آیا همیشه باید از `const` استفاده کنیم؟

یکی از توصیه‌های مهم Jonas Schmedtmann این است که:

> همیشه کار را با `const` آغاز کنید.

اگر بعداً مشخص شد که مقدار Variable باید تغییر کند، آن را به `let` تبدیل کنید.

این روش چند مزیت مهم دارد:

- احتمال تغییر ناخواسته Variable کاهش پیدا می‌کند.
- خوانایی کد بیشتر می‌شود.
- Intent برنامه‌نویس از روی Declaration واضح‌تر است.
- بسیاری از خطاها در زمان توسعه شناسایی می‌شوند.

این رویکرد در بخش بزرگی از پروژه‌های مدرن JavaScript قابل استفاده است.

---

# `var` امروز چه جایگاهی دارد؟

اکنون که با `let` و `const` آشنا شدیم، می‌توانیم جایگاه `var` را بهتر درک کنیم.

در پروژه‌های مدرن معمولاً دلیلی برای استفاده از `var` وجود ندارد.

دلیل این موضوع صرفاً قدیمی بودن `var` نیست.

بلکه رفتار آن در مقایسه با `let` و `const` در مواردی کمتر قابل پیش‌بینی است.

به همین دلیل، در کدهای مدرن معمولاً:

- برای مقادیری که نباید دوباره Assignment شوند از `const`
- برای مقادیری که باید تغییر کنند از `let`
- و `var` بیشتر هنگام کار با کدهای قدیمی یا بررسی رفتار تاریخی JavaScript دیده می‌شود.

---

# چه زمانی از `let` و چه زمانی از `const` استفاده کنیم؟

قاعده‌ای ساده وجود دارد.

اگر Variable قرار نیست دوباره Assignment شود:

```javascript
const apiURL = 'https://api.example.com';
```

اگر تغییر مقدار بخشی از منطق برنامه است:

```javascript
let counter = 0;

counter++;
```

همین قانون ساده، در بخش بزرگی از پروژه‌های JavaScript قابل استفاده است.

❌ `var` دیگر در JavaScript وجود ندارد.

✔ `var` همچنان بخشی از زبان است، اما در توسعه نرم‌افزارهای جدید معمولاً انتخاب مناسبی نیست.

# نکات مهم

- `const` مانند `let` دارای **Block Scope** است.
- Variableهای `const` باید هنگام Declaration مقداردهی اولیه شوند.
- Binding یک Variable `const` پس از Initialization تغییر نمی‌کند.
- Propertyهای یک Object یا عناصر یک Array که با `const` تعریف شده‌اند همچنان می‌توانند تغییر کنند.
- در پروژه‌های مدرن، `const` انتخاب اول برای تعریف Variableها است.
- تنها زمانی از `let` استفاده کنید که تغییر مقدار Variable بخشی از منطق برنامه باشد.

---

# Scope and Hoisting Preview

تا اینجا دیدیم که `let` و `const` دارای Block Scope هستند.

اما تفاوت میان `var`، `let` و `const` فقط به Scope محدود نمی‌شود.

JavaScript پیش از اجرای کد، Declarationهای مربوط به Variableها را در محیط اجرای خود مدیریت می‌کند.

این رفتار در مورد `var`، `let` و `const` کاملاً یکسان نیست.

برای مثال، `var` می‌تواند رفتاری داشته باشد که دسترسی به Variable پیش از محل Declaration در بعضی شرایط به `undefined` منجر شود.

در مقابل، `let` و `const` پیش از Initialization قابل دسترسی نیستند.

در این مرحله لازم نیست جزئیات این رفتار را بررسی کنیم.

مفهوم **Hoisting** و دلیل تفاوت دقیق رفتار `var`، `let` و `const` در فصل **Hoisting and Temporal Dead Zone** به‌صورت کامل بررسی خواهد شد.

---

# نکته مهندسی

اکنون می‌توانیم یک قاعده عملی ساده برای انتخاب روش Declaration داشته باشیم:

```text
قرار نیست دوباره Assignment شود؟
        ↓
      const

باید دوباره Assignment شود؟
        ↓
       let

کد قدیمی یا بررسی رفتار تاریخی؟
        ↓
       var
```

این قاعده، انتخاب Declaration را از یک موضوع صرفاً Syntax به یک تصمیم مهندسی تبدیل می‌کند.

# خلاصه فصل

در این فصل با یکی از مهم‌ترین تغییرات JavaScript مدرن آشنا شدیم.

در نسخه‌های اولیه این زبان، تنها روش تعریف Variableها استفاده از `var` بود. با بزرگ‌تر شدن پروژه‌ها، مشخص شد که رفتار `var` در بسیاری از شرایط باعث کاهش خوانایی کد و افزایش احتمال بروز خطا می‌شود.

به همین دلیل، در استاندارد **ECMAScript 2015 (ES6)** دو کلمه کلیدی جدید، یعنی `let` و `const` معرفی شدند.

در ادامه دیدیم که:

- `let` برای Variableهایی مناسب است که مقدار آن‌ها در طول اجرای برنامه تغییر می‌کند.
- `const` برای Variableهایی مناسب است که نباید به مقدار دیگری Assignment شوند.
- `let` و `const` دارای **Block Scope** هستند.
- `const` یک **Immutable Binding** ایجاد می‌کند و لزوماً محتوای Object را غیرقابل تغییر نمی‌کند.
- رفتار `var`، `let` و `const` در ارتباط با Hoisting یکسان نیست و جزئیات آن در فصل‌های آینده بررسی خواهد شد.

در پایان نیز با یکی از مهم‌ترین توصیه‌های توسعه‌دهندگان حرفه‌ای آشنا شدیم:

> **تا زمانی که مجبور نشده‌اید، از `const` استفاده کنید.**

---

# Key Takeaways

در پایان این فصل باید بتوانید نکات زیر را به‌صورت دقیق توضیح دهید:

- `var` روش قدیمی تعریف Variable در JavaScript است.
- `let` برای Variableهای قابل تغییر استفاده می‌شود.
- `const` برای Variableهایی است که نباید به مقدار دیگری Assignment شوند.
- `let` و `const` دارای **Block Scope** هستند.
- `const` مقدار Object را ثابت نمی‌کند؛ بلکه Binding مربوط به Variable را ثابت نگه می‌دارد.
- رفتار `var`، `let` و `const` در ارتباط با Hoisting یکسان نیست.
- استفاده از `const` باعث می‌شود Intent کد واضح‌تر شود و تغییر ناخواسته Bindingها کاهش پیدا کند.
- در پروژه‌های مدرن، استفاده از `var` معمولاً توصیه نمی‌شود.

# Golden Answers

## تفاوت `var`، `let` و `const`

`var` روش قدیمی تعریف Variable است.  
`let` برای Variableهای قابل تغییر استفاده می‌شود.  
`const` برای Variableهایی است که نباید به مقدار دیگری Assignment شوند.

---

## Block Scope چیست؟

Block Scope محدوده‌ای از برنامه است که با آکولاد (`{}`) مشخص می‌شود و Variableهای تعریف‌شده با `let` و `const` فقط در همان محدوده قابل دسترسی هستند.

---

## آیا `const` مقدار را ثابت می‌کند؟

خیر.

`const` مقدار Object را ثابت نمی‌کند؛ بلکه Binding مربوط به Variable را ثابت نگه می‌دارد.

---

## Immutable Binding یعنی چه؟

یعنی Binding یک Variable `const` پس از Initialization نمی‌تواند به مقدار دیگری Assignment شود.

---

## چرا استفاده از `const` توصیه می‌شود؟

زیرا:

- خوانایی کد را افزایش می‌دهد.
- احتمال تغییر ناخواسته Binding را کاهش می‌دهد.
- Intent برنامه‌نویس را واضح‌تر می‌کند.
- برخی خطاها را در زمان توسعه آشکار می‌کند.

---

## پاسخ کوتاه طلایی مصاحبه

**سؤال**

اگر بخواهید تنها یک قانون برای انتخاب میان `let` و `const` بیان کنید، آن قانون چیست؟

**پاسخ**

همیشه ابتدا از `const` استفاده کنید و تنها زمانی به `let` مراجعه کنید که تغییر مقدار Variable بخشی از منطق برنامه باشد.

# جمع‌بندی فصل

Variableها نقطه شروع تقریباً تمام برنامه‌های JavaScript هستند، اما انتخاب روش مناسب برای تعریف آن‌ها نیز به همان اندازه اهمیت دارد.

در این فصل آموختیم که سه کلمه کلیدی `var`، `let` و `const` اگرچه همگی برای تعریف Variable استفاده می‌شوند، اما فلسفه طراحی و رفتار متفاوتی دارند.

شناخت این تفاوت‌ها باعث می‌شود کدهایی بنویسیم که خواناتر، قابل پیش‌بینی‌تر و نگهداری آن‌ها آسان‌تر باشد.

از این فصل به بعد، در مثال‌های کتاب از همان استانداردی استفاده خواهیم کرد که امروزه در بسیاری از پروژه‌های حرفه‌ای JavaScript رایج است؛ یعنی:

- **`const` انتخاب اول**
- **`let` در صورت نیاز به تغییر مقدار**
- **پرهیز از `var` مگر برای بررسی کدهای قدیمی یا رفتار تاریخی زبان**

در فصل بعد، با **Operatorها و Expressionها** آشنا خواهیم شد و خواهیم دید که JavaScript چگونه با استفاده از Operatorهای مختلف، روی Valueها عملیات انجام می‌دهد.
