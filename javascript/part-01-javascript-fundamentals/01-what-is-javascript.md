# اهداف فصل

پس از مطالعه این فصل، انتظار می‌رود بتوانید:

- JavaScript را به‌صورت دقیق و مهندسی تعریف کنید.
- تفاوت JavaScript، ECMAScript، JavaScript Engine و Runtime را توضیح دهید.
- مفهوم High-Level، Dynamic، Multi-Paradigm و Object-Oriented را در JavaScript درک کنید.
- تفاوت کلی میان Interpretation، Compilation و JIT Compilation را توضیح دهید.
- تفاوت Browser Runtime و Server-Side Runtime را در سطح مفهومی درک کنید.
- جایگاه JavaScript را در دنیای توسعه نرم‌افزار مدرن بشناسید.
- به رایج‌ترین پرسش‌های مصاحبه فنی این مبحث پاسخ دهید.
- مدل ذهنی صحیحی برای ادامه یادگیری JavaScript در فصل‌های بعد به دست آورید.

---

# مقدمه

بیشتر افراد یادگیری JavaScript را با حفظ کردن سینتکس آغاز می‌کنند. آن‌ها با متغیرها، توابع، شرط‌ها و حلقه‌ها آشنا می‌شوند و تصور می‌کنند هرچه تعداد بیشتری از دستورات زبان را بدانند، برنامه‌نویس بهتری خواهند بود.

این روش شاید در کوتاه‌مدت باعث شود چند برنامه ساده نوشته شود، اما در بلندمدت معمولاً به بن‌بست می‌رسد. دلیل این موضوع آن است که JavaScript صرفاً مجموعه‌ای از کلمات کلیدی و قوانین نگارشی نیست؛ بلکه سیستمی است که بر پایه مجموعه‌ای از مفاهیم، استانداردها و مدل‌های اجرایی طراحی شده است. اگر این مفاهیم به‌درستی درک نشوند، بسیاری از رفتارهای زبان عجیب، غیرقابل پیش‌بینی یا حتی اشتباه به نظر خواهند رسید.

هدف این کتاب آموزش دستورات JavaScript نیست؛ هدف آن ساختن یک مدل ذهنی صحیح است. هنگامی که این مدل ذهنی شکل بگیرد، یادگیری قابلیت‌های جدید زبان بسیار ساده‌تر خواهد شد و بسیاری از رفتارهایی که در نگاه اول پیچیده به نظر می‌رسند، کاملاً منطقی خواهند بود.

به همین دلیل، پیش از آنکه وارد مباحثی مانند متغیرها، انواع داده، توابع یا شیءها شویم، ابتدا باید بدانیم دقیقاً با چه زبانی روبه‌رو هستیم.

# JavaScript چیست؟

اگر همین سؤال را از افراد مختلف بپرسید، احتمالاً پاسخ‌های متفاوتی خواهید شنید.

برخی خواهند گفت:

> JavaScript زبان برنامه‌نویسی صفحات وب است.

عده‌ای دیگر پاسخ خواهند داد:

> زبانی است که در مرورگر اجرا می‌شود.

بعضی نیز آن را این‌گونه معرفی می‌کنند:

> زبانی برای ایجاد تعامل در صفحات وب.

هیچ‌یک از این پاسخ‌ها کاملاً اشتباه نیستند، اما هیچ‌کدام نیز تصویر کاملی از JavaScript ارائه نمی‌کنند.

تعریفی که یک توسعه‌دهنده حرفه‌ای از JavaScript ارائه می‌دهد، بسیار دقیق‌تر است.

---

## تعریف ساده

JavaScript یک زبان برنامه‌نویسی است که برای ساخت نرم‌افزارهای تعاملی طراحی شده و امروزه در محیط‌های مختلفی مانند مرورگر، سرور، برنامه‌های موبایل و حتی برنامه‌های دسکتاپ اجرا می‌شود.

این تعریف برای شروع مناسب است، اما هنوز بسیاری از ویژگی‌های مهم JavaScript را بیان نمی‌کند.

---

## تعریف فنی

JavaScript یک **زبان برنامه‌نویسی سطح بالا (High-Level)، چندپارادایمی (Multi-Paradigm)، شیءگرا (Object-Oriented)، دارای مدیریت خودکار حافظه (Garbage Collected) و پویا (Dynamic)** است که مشخصات آن توسط استاندارد **ECMAScript** تعریف می‌شود و توسط موتورهای اجرای مختلف در Runtimeهای گوناگون اجرا می‌شود.

هر کلمه در این تعریف معنا و اهمیت خاص خود را دارد.

در ادامه این فصل، تمام این ویژگی‌ها به‌صورت دقیق بررسی خواهند شد.

---

# چرا این تعریف اهمیت دارد؟

فرض کنید تنها این جمله را حفظ کنید:

> JavaScript زبان برنامه‌نویسی صفحات وب است.

این جمله اگرچه از نظر تاریخی تا حدی درست است، اما باعث شکل‌گیری یک مدل ذهنی نادرست می‌شود.

اگر چنین تصوری داشته باشید، احتمالاً در ادامه با پرسش‌هایی روبه‌رو خواهید شد که پاسخ آن‌ها برایتان مبهم خواهد بود.

برای مثال:

- چرا JavaScript روی سرور نیز اجرا می‌شود؟
- Node.js چیست؟
- اگر JavaScript زبان مرورگر است، پس Deno و Bun چه هستند؟
- تفاوت JavaScript با ECMAScript چیست؟
- آیا DOM بخشی از JavaScript است؟
- چرا بعضی قابلیت‌ها در مرورگر وجود دارند اما در Node.js وجود ندارند؟

تمام این پرسش‌ها نشان می‌دهد که تعریف ساده JavaScript برای درک صحیح این زبان کافی نیست.

---

# JavaScript فقط یک زبان نیست

یکی از بزرگ‌ترین اشتباهات برنامه‌نویسان تازه‌کار این است که JavaScript را تنها مجموعه‌ای از سینتکس‌ها می‌بینند.

برای مثال:

```javascript
const user = {
  firstName: "Omid",
  age: 58,
};
```

بسیاری تصور می‌کنند تمام اتفاقی که رخ می‌دهد همین چند خط کد است.

در حالی که این تنها بخش کوچکی از فرآیند اجرای برنامه است.

وقتی چنین کدی نوشته می‌شود، در پشت صحنه اجزای مختلفی با یکدیگر همکاری می‌کنند.

در ساده‌ترین نگاه، چهار مفهوم مستقل وجود دارد:

1. زبان JavaScript
2. استاندارد ECMAScript
3. موتور اجرای JavaScript (JavaScript Engine)
4. محیط اجرا (Runtime)

درک تفاوت این چهار مفهوم یکی از مهم‌ترین اهداف این فصل است؛ زیرا بسیاری از سوءبرداشت‌های رایج دقیقاً از یکسان در نظر گرفتن این مفاهیم ناشی می‌شوند.

در فصل‌های بعد خواهیم دید که بسیاری از قابلیت‌هایی که برنامه‌نویسان به اشتباه جزئی از JavaScript می‌دانند، در واقع متعلق به Runtime هستند و نه خود زبان.

---

# برنامه‌نویسی یعنی حل مسئله

یکی از اشتباهات رایج در آموزش برنامه‌نویسی این است که از همان ابتدا تمرکز بر روی دستورات زبان قرار می‌گیرد.

در نتیجه، دانشجو تصور می‌کند برنامه‌نویسی یعنی حفظ کردن دستورها و سپس کنار هم قرار دادن آن‌ها.

اما حقیقت چیز دیگری است.

برنامه‌نویسی پیش از آنکه نوشتن کد باشد، حل مسئله است.

هر برنامه‌ای که نوشته می‌شود، پاسخی برای یک مسئله واقعی است.

کد تنها وسیله‌ای برای بیان آن پاسخ است.

به همین دلیل، در این کتاب تلاش خواهیم کرد پیش از معرفی هر قابلیت، ابتدا مسئله‌ای را که آن قابلیت برای حل آن ایجاد شده است بررسی کنیم.

این رویکرد باعث می‌شود مطالب به جای حفظ شدن، درک شوند و در پروژه‌های واقعی نیز قابل استفاده باشند.

---پیش از پاسخ دادن به این پرسش، لازم است چند ویژگی مهم JavaScript را بشناسیم؛ ویژگی‌هایی که تقریباً در تمام معرفی‌های رسمی این زبان مشاهده می‌شوند، اما معمولاً بدون توضیح از کنار آن‌ها عبور می‌شود.

تقریباً در تمام مستندات فنی، JavaScript با مجموعه‌ای از صفت‌ها معرفی می‌شود:

- High-Level
- Multi-Paradigm
- Object-Oriented
- Prototype-Based
- Dynamic
- Garbage-Collected

اگر این واژه‌ها را تنها حفظ کنید، در عمل کمکی به درک زبان نخواهند کرد. اما اگر بدانید هر یک دقیقاً چه مفهومی دارند و چرا JavaScript با این ویژگی‌ها شناخته می‌شود، در ادامه مسیر یادگیری بسیاری از رفتارهای این زبان برایتان بدیهی و منطقی خواهد شد.

---

# منظور از High-Level چیست؟

یکی از اولین ویژگی‌هایی که تقریباً در تمام معرفی‌های JavaScript مشاهده می‌شود، عبارت **High-Level Programming Language** است.

اما این اصطلاح دقیقاً چه معنایی دارد؟

برای پاسخ به این سؤال ابتدا باید بدانیم کامپیوتر چگونه برنامه‌ها را اجرا می‌کند.

پردازنده تنها زبان ماشین را متوجه می‌شود؛ زبانی متشکل از صفر و یک که مستقیماً توسط سخت‌افزار اجرا می‌شود.

نمونه‌ای از زبان ماشین ممکن است چیزی شبیه این باشد:

```text
10110000 01100001
10110001 01100010
11000011
```

واضح است که نوشتن برنامه با چنین زبانی برای انسان تقریباً غیرممکن است.

به همین دلیل زبان‌های برنامه‌نویسی به وجود آمدند تا فاصله میان انسان و سخت‌افزار را کاهش دهند.

---

## تعریف High-Level Language

زبان‌های برنامه‌نویسی را معمولاً از نظر میزان نزدیکی به سخت‌افزار به دو گروه کلی تقسیم می‌کنند:

- Low-Level Languages
- High-Level Languages

زبان‌های سطح پایین، کنترل بسیار زیادی روی سخت‌افزار در اختیار برنامه‌نویس قرار می‌دهند، اما نوشتن برنامه با آن‌ها دشوارتر است.

در مقابل، زبان‌های سطح بالا بسیاری از جزئیات پیچیده سخت‌افزار را از دید برنامه‌نویس پنهان می‌کنند و اجازه می‌دهند تمرکز اصلی روی حل مسئله باشد.

به این پنهان‌سازی جزئیات **Abstraction** گفته می‌شود.

در حقیقت، هرچه سطح انتزاع یک زبان بیشتر باشد، برنامه‌نویس کمتر درگیر جزئیات داخلی سیستم خواهد شد.

JavaScript یکی از زبان‌هایی است که سطح انتزاع بسیار بالایی دارد.

---

## منظور از Abstraction چیست؟

فرض کنید قصد دارید با یک خودرو رانندگی کنید.

برای حرکت دادن خودرو لازم نیست بدانید:

- پیستون‌ها چگونه حرکت می‌کنند.
- سیستم احتراق چگونه کار می‌کند.
- سوپاپ‌ها در چه زمانی باز و بسته می‌شوند.
- ECU چگونه موتور را کنترل می‌کند.

تمام این پیچیدگی‌ها پشت یک فرمان، چند پدال و یک دسته‌دنده پنهان شده‌اند.

این دقیقاً همان چیزی است که در علوم کامپیوتر **Abstraction** نامیده می‌شود.

زبان‌های سطح بالا نیز همین کار را انجام می‌دهند.

به جای آنکه برنامه‌نویس مستقیماً با حافظه، ثبات‌های پردازنده یا دستورهای ماشین سروکار داشته باشد، تنها کافی است مفاهیم سطح بالاتری مانند متغیر، تابع یا شیء را به کار ببرد.

---

## JavaScript چه چیزهایی را از ما پنهان می‌کند؟

یکی از مهم‌ترین ویژگی‌های JavaScript این است که بسیاری از عملیات پیچیده را به‌صورت خودکار انجام می‌دهد.

برای مثال، زمانی که یک شیء ایجاد می‌کنید:

```javascript
const user = {
  firstName: "Omid",
  age: 58,
};
```

نیازی نیست بدانید:

- این شیء در کدام بخش حافظه قرار گرفته است.
- چه مقدار حافظه برای آن رزرو شده است.
- چه زمانی باید حافظه آن آزاد شود.
- آدرس حافظه آن چیست.

تمام این عملیات توسط موتور اجرای JavaScript مدیریت می‌شود.

---

## Garbage Collection

یکی از مهم‌ترین قابلیت‌هایی که باعث شده JavaScript یک زبان سطح بالا محسوب شود، **مدیریت خودکار حافظه** است.

در زبان‌هایی مانند C یا ++C برنامه‌نویس باید خودش حافظه را تخصیص دهد و در زمان مناسب آن را آزاد کند.

اگر این کار فراموش شود، برنامه دچار نشت حافظه (Memory Leak) خواهد شد.

اما در JavaScript چنین مسئولیتی بر عهده برنامه‌نویس نیست.

موتور JavaScript به‌طور مداوم اشیایی را که دیگر مورد استفاده قرار نمی‌گیرند شناسایی کرده و حافظه آن‌ها را آزاد می‌کند.

به این فرآیند **Garbage Collection** گفته می‌شود.

وجود چنین قابلیتی یکی از مهم‌ترین دلایل سطح بالای JavaScript است.

---

## آیا High-Level بودن فقط مزیت است؟

خیر.

هر سطح انتزاعی، علاوه بر مزایا، هزینه‌هایی نیز دارد.

از مهم‌ترین مزایای زبان‌های سطح بالا می‌توان به موارد زیر اشاره کرد:

- خوانایی بیشتر
- توسعه سریع‌تر
- کاهش خطاهای مرتبط با حافظه
- نگهداری آسان‌تر پروژه‌ها
- افزایش بهره‌وری برنامه‌نویس

در مقابل، مهم‌ترین محدودیت آن‌ها این است که کنترل مستقیم روی سخت‌افزار کمتر می‌شود و موتور اجرا باید بخشی از عملیات را به‌صورت خودکار انجام دهد.

البته موتورهای مدرن JavaScript مانند V8 با استفاده از تکنیک‌هایی مانند **Just-In-Time Compilation (JIT)** این محدودیت را تا حد زیادی جبران کرده‌اند؛ موضوعی که در فصل JavaScript Engine به‌صورت کامل بررسی خواهیم کرد.

## اشتباه رایج

بعضی افراد تصور می‌کنند High-Level بودن یعنی زبان کند است.

این برداشت دقیق نیست.

سطح انتزاع و سرعت اجرا دو مفهوم متفاوت هستند.

سرعت واقعی اجرای یک برنامه علاوه بر خود زبان، به کیفیت موتور اجرا، نحوه پیاده‌سازی الگوریتم و بسیاری عوامل دیگر بستگی دارد.

به همین دلیل، JavaScript با وجود High-Level بودن، امروزه در بسیاری از برنامه‌های بزرگ و پیچیده مورد استفاده قرار می‌گیرد.

# Dynamic بودن JavaScript یعنی چه؟

یکی دیگر از ویژگی‌های بنیادی JavaScript، **Dynamic بودن** آن است.

وقتی می‌گوییم JavaScript یک زبان Dynamic است، منظور این است که نوع یک Value در زمان اجرای برنامه مشخص می‌شود و یک Variable الزاماً از ابتدا به یک Type ثابت محدود نمی‌شود.

برای مثال:

```javascript
let value = 42;

value = "JavaScript";
```

در این مثال، Variable به نام `value` ابتدا یک Number را نگه می‌دارد و بعداً یک String را دریافت می‌کند.

این رفتار با زبان‌هایی که در آن‌ها Type یک Variable از ابتدا به‌صورت سخت‌گیرانه مشخص می‌شود متفاوت است.

---

## تعریف فنی

JavaScript یک زبان **Dynamically Typed** است؛ یعنی Type به Value تعلق دارد و Type Checking مربوط به Valueها در زمان اجرای برنامه انجام می‌شود.

به همین دلیل، هنگام تعریف یک Variable لازم نیست Type آن را به‌صورت صریح مشخص کنیم.

```javascript
let productCount = 10;
let productName = "Laptop";
```

در این مثال، JavaScript Type هر Value را در Runtime مدیریت می‌کند.

---

## چرا Dynamic بودن مهم است؟

Dynamic Typing باعث می‌شود نوشتن کد در JavaScript انعطاف‌پذیر باشد.

در مقابل، همین انعطاف‌پذیری می‌تواند باعث ایجاد خطاهایی شود که در زمان نوشتن کد به‌سادگی قابل مشاهده نیستند.

برای مثال:

```javascript
let price = 100;

price = "100";
```

کد از نظر Syntax معتبر است، اما تغییر Type ممکن است در ادامه رفتار متفاوتی ایجاد کند.

به همین دلیل، در JavaScript باید تفاوت میان **Variable، Value و Type** را به‌درستی درک کنیم.

این موضوع در فصل **Data Types** به‌صورت کامل بررسی خواهد شد.

---

## اشتباه رایج

Dynamic بودن به این معنا نیست که JavaScript «بدون Type» است.

JavaScript کاملاً دارای Type است؛ اما Typeها در زمان اجرای برنامه به Valueها مربوط می‌شوند و Variableها الزاماً Type ثابت ندارند.

---

## پاسخ کوتاه طلایی مصاحبه

**سؤال**

Dynamic بودن JavaScript یعنی چه؟

**پاسخ**

JavaScript یک زبان Dynamically Typed است؛ یعنی Type به Value مربوط است و بررسی Type در Runtime انجام می‌شود. بنابراین یک Variable می‌تواند در زمان‌های مختلف Valueهایی با Typeهای متفاوت نگه‌داری کند.

---

# Interpreted یا Compiled؟

یکی از قدیمی‌ترین پرسش‌ها درباره JavaScript این است:

> آیا JavaScript یک زبان Interpreted است یا Compiled؟

پاسخ ساده‌ای مانند «JavaScript یک زبان Interpreted است» امروزه تصویر دقیقی از نحوه اجرای JavaScript ارائه نمی‌کند.

برای درک این موضوع ابتدا باید دو مفهوم را از هم جدا کنیم.

---

## Interpretation چیست؟

در یک مدل ساده، Interpreter کد را دریافت می‌کند و آن را برای اجرا پردازش می‌کند.

در این مدل، تمرکز اصلی روی اجرای مستقیم برنامه از طریق یک سیستم تفسیر است.

---

## Compilation چیست؟

در Compilation، Source Code پیش از اجرای نهایی به شکلی تبدیل می‌شود که برای اجرا مناسب‌تر باشد.

این تبدیل می‌تواند به تولید Machine Code یا یک نمایش میانی منجر شود.

---

## JavaScript چگونه اجرا می‌شود؟

موتورهای مدرن JavaScript از یک روش واحد و ساده مانند «فقط Interpretation» یا «فقط Compilation» استفاده نمی‌کنند.

آن‌ها از تکنیک‌های مختلفی برای پردازش و اجرای کد استفاده می‌کنند.

به همین دلیل، بهتر است به‌جای این جمله:

> JavaScript یک زبان Interpreted است.

بگوییم:

> JavaScript در Runtime توسط یک JavaScript Engine پردازش و اجرا می‌شود و موتورهای مدرن از ترکیبی از Interpretation و Compilation استفاده می‌کنند.

این نگاه، مدل ذهنی دقیق‌تری ایجاد می‌کند.

---

# JIT Compilation چیست؟

یکی از تکنیک‌های مهم در موتورهای مدرن JavaScript، **Just-In-Time Compilation** یا **JIT Compilation** است.

JIT را می‌توان به‌صورت ساده فرآیندی دانست که در زمان اجرای برنامه، بخش‌هایی از کد را برای اجرای کارآمدتر به شکل مناسب‌تری کامپایل و بهینه می‌کند.

در نتیجه، موتور می‌تواند بر اساس اطلاعاتی که هنگام اجرای برنامه به دست می‌آورد، برای مسیرهای پرتکرار برنامه بهینه‌سازی انجام دهد.

مدل ذهنی ساده آن به این شکل است:

```text
JavaScript Source Code
        ↓
JavaScript Engine
        ↓
Processing / Execution
        ↓
Runtime Information
        ↓
Optimization / JIT
        ↓
Efficient Execution
```

هدف این بخش، توضیح جزئیات داخلی JIT نیست.

جزئیات Parsing، AST، Compilation، Optimization و JIT در فصل **JavaScript Engine and Runtime** بررسی خواهند شد.

---

## چرا این موضوع مهم است؟

شناخت JIT کمک می‌کند یک سوءبرداشت رایج را اصلاح کنیم:

> High-Level بودن JavaScript به معنای اجرای ساده یا ذاتاً کند بودن آن نیست.

موتورهای مدرن می‌توانند هنگام اجرای برنامه، اطلاعات واقعی Runtime را بررسی کرده و بخش‌هایی از کد را برای اجرای بهتر بهینه کنند.

---

## اشتباه رایج

❌ JavaScript فقط یک زبان Interpreted است.

✔ JavaScript در Runtime توسط Engine اجرا می‌شود و موتورهای مدرن می‌توانند از Interpretation، Compilation و JIT Techniques استفاده کنند.

---

## پاسخ کوتاه طلایی مصاحبه

**سؤال**

آیا JavaScript یک زبان Interpreted است یا Compiled؟

**پاسخ**

تقسیم‌بندی ساده JavaScript به «فقط Interpreted» یا «فقط Compiled» دقیق نیست. موتورهای مدرن JavaScript از تکنیک‌های مختلفی از جمله Compilation و JIT برای اجرای بهینه کد استفاده می‌کنند.

---


# Multi-Paradigm یعنی چه؟

یکی دیگر از ویژگی‌هایی که تقریباً در تمام معرفی‌های JavaScript مشاهده می‌شود، عبارت **Multi-Paradigm Programming Language** است.

در نگاه اول، این عبارت ممکن است صرفاً یک اصطلاح تخصصی به نظر برسد؛ اما در واقع یکی از مهم‌ترین ویژگی‌های JavaScript است و بخش بزرگی از انعطاف‌پذیری این زبان از همین قابلیت ناشی می‌شود.

برای درک مفهوم Multi-Paradigm ابتدا باید بدانیم **Paradigm** چیست.

---

## Paradigm چیست؟

واژه Paradigm را می‌توان به «سبک برنامه‌نویسی» یا «روش حل مسئله» ترجمه کرد.

همان‌طور که برای حل یک مسئله ریاضی می‌توان از روش‌های مختلف استفاده کرد، در برنامه‌نویسی نیز می‌توان یک مسئله را با سبک‌های متفاوتی حل کرد.

به بیان ساده، Paradigm مشخص می‌کند که برنامه‌نویس چگونه درباره مسئله فکر کند و ساختار برنامه را چگونه طراحی نماید.

در طول تاریخ برنامه‌نویسی، پارادایم‌های مختلفی معرفی شده‌اند، اما سه پارادایم بیش از سایرین مورد استفاده قرار گرفته‌اند:

- Procedural Programming
- Object-Oriented Programming
- Functional Programming

JavaScript هر سه پارادایم را پشتیبانی می‌کند و به همین دلیل یک زبان **Multi-Paradigm** محسوب می‌شود.

---

# برنامه‌نویسی رویه‌ای (Procedural Programming)

برنامه‌نویسی رویه‌ای قدیمی‌ترین و ساده‌ترین سبک برنامه‌نویسی است.

در این روش، برنامه به مجموعه‌ای از دستورات و توابع تقسیم می‌شود که به‌ترتیب اجرا می‌شوند.

برای مثال:

```javascript
function calculatePrice(price, tax) {
  return price + price * tax;
}

const total = calculatePrice(100, 0.1);
```

در این مثال، تمرکز برنامه روی اجرای یک تابع است.

در پروژه‌های کوچک، این روش کاملاً مناسب است؛ اما هرچه اندازه پروژه افزایش پیدا کند، مدیریت وابستگی‌ها و نگهداری کد دشوارتر می‌شود.

---

# برنامه‌نویسی شیءگرا (Object-Oriented Programming)

در برنامه‌نویسی شیءگرا، تمرکز از «توابع» به «اشیاء» منتقل می‌شود.

در این روش، داده و رفتار مرتبط با آن داده در کنار یکدیگر قرار می‌گیرند.

برای مثال:

```javascript
const account = {
  owner: "Omid",

  deposit(amount) {
    console.log(`${amount} deposited`);
  },
};
```

در این مثال، شیء account تنها مجموعه‌ای از داده‌ها نیست؛ بلکه رفتار مربوط به آن نیز درون همان شیء قرار گرفته است.

این رویکرد باعث می‌شود پروژه‌های بزرگ ساختار منظم‌تر و قابل نگهداری‌تری داشته باشند.

در فصل‌های آینده، شیءگرایی در JavaScript را به‌صورت کامل بررسی خواهیم کرد.

---

# برنامه‌نویسی تابعی (Functional Programming)

پارادایم سوم، برنامه‌نویسی تابعی است.

در این سبک، تابع به مهم‌ترین عنصر برنامه تبدیل می‌شود.

ویژگی مهم JavaScript این است که توابع در این زبان **First-Class Citizen** هستند.

این یعنی:

- می‌توان تابع را داخل متغیر ذخیره کرد.
- می‌توان تابع را به تابع دیگری ارسال کرد.
- می‌توان تابع را از داخل یک تابع بازگرداند.
- می‌توان توابع را مانند سایر داده‌ها مدیریت کرد.

برای مثال:

```javascript
const greet = function () {
  console.log("Hello");
};

const execute = greet;

execute();
```

وجود چنین قابلیتی باعث شده JavaScript برای برنامه‌نویسی تابعی نیز زبان بسیار مناسبی باشد.

---

# چرا Multi-Paradigm بودن مهم است؟

برخی زبان‌ها تقریباً شما را مجبور می‌کنند از یک سبک مشخص استفاده کنید.

اما JavaScript چنین محدودیتی ندارد.

شما می‌توانید:

- بخش کوچکی از برنامه را به‌صورت رویه‌ای بنویسید.
- قسمت دیگری را با رویکرد شیءگرا طراحی کنید.
- و در بخش‌هایی که مناسب‌تر است، از تکنیک‌های برنامه‌نویسی تابعی استفاده کنید.

این انعطاف‌پذیری یکی از مهم‌ترین دلایل محبوبیت JavaScript است.

---

# اشتباه رایج

گاهی گفته می‌شود:

> JavaScript یک زبان شیءگرا است.

این جمله کامل نیست.

همچنین گفته می‌شود:

> JavaScript یک زبان تابعی است.

این نیز تعریف دقیقی نیست.

تعریف صحیح این است:

> JavaScript یک زبان Multi-Paradigm است که از برنامه‌نویسی رویه‌ای، شیءگرا و تابعی پشتیبانی می‌کند.

همین ویژگی باعث می‌شود توسعه‌دهنده بتواند برای هر مسئله، مناسب‌ترین سبک طراحی را انتخاب کند.

---

# پاسخ کوتاه طلایی مصاحبه

**سؤال**

منظور از Multi-Paradigm بودن JavaScript چیست؟

**پاسخ**

JavaScript محدود به یک سبک برنامه‌نویسی نیست و از چندین پارادایم از جمله Procedural، Object-Oriented و Functional Programming پشتیبانی می‌کند. این ویژگی باعث می‌شود برنامه‌نویس بتواند متناسب با مسئله، بهترین روش طراحی را انتخاب کند.

---

# آیا JavaScript یک زبان Object-Oriented است؟

این سؤال یکی از رایج‌ترین پرسش‌های مصاحبه‌های فنی است و پاسخ آن معمولاً با یک سوءبرداشت همراه است.

بسیاری از برنامه‌نویسان تصور می‌کنند تنها زبان‌هایی مانند Java یا C# شیءگرا هستند؛ زیرا از کلاس‌ها (Class) استفاده می‌کنند.

اما JavaScript سال‌ها پیش از معرفی کلاس‌ها نیز یک زبان شیءگرا بود.

دلیل این موضوع آن است که **شیءگرایی در JavaScript بر پایه Prototype طراحی شده است، نه بر پایه Class.**

کلاس‌هایی که امروزه در JavaScript می‌بینید، از نسخه ES2015 به زبان اضافه شده‌اند، اما در حقیقت یک **لایه نحوی (Syntactic Sugar)** روی همان سیستم Prototype هستند و مدل بنیادی زبان را تغییر نداده‌اند.

در فصل «Objects and Prototypes» این موضوع را با جزئیات کامل بررسی خواهیم کرد.

---

# چرا Jonas Schmedtmann روی Object-Oriented بودن JavaScript تأکید می‌کند؟

یکی از نکاتی که Jonas بارها در دوره خود بر آن تأکید می‌کند این است که:

> اگر مدل شیءگرایی JavaScript را درک نکنید، بخش بزرگی از رفتار این زبان برایتان مبهم باقی خواهد ماند.

دلیل این تأکید روشن است.

بخش بزرگی از قابلیت‌های JavaScript مانند:

- Array
- Function
- Date
- Map
- Set
- Promise

همگی شیء هستند و از سیستم Prototype استفاده می‌کنند.

اگر تصور کنید شیءگرایی در JavaScript فقط به کلاس‌ها محدود می‌شود، درک بسیاری از مفاهیم پیشرفته مانند Prototype Chain، Inheritance و Delegation دشوار خواهد شد.

بنابراین، شیءگرایی در JavaScript یک قابلیت جانبی نیست؛ بلکه بخشی از هویت این زبان است.

# ECMAScript چیست؟

تا اینجا چندین بار از واژه **ECMAScript** استفاده کردیم، اما هنوز دقیقاً مشخص نکرده‌ایم که این واژه به چه معناست.

یکی از رایج‌ترین اشتباهات برنامه‌نویسان تازه‌کار این است که JavaScript و ECMAScript را یک مفهوم واحد در نظر می‌گیرند.

برای مثال، ممکن است بشنوید:

> JavaScript همان ECMAScript است.

یا

> ECMAScript نسخه جدید JavaScript است.

هیچ‌یک از این دو جمله دقیق نیستند.

برای درک صحیح این موضوع، ابتدا باید بدانیم «استاندارد» (Standard) در دنیای نرم‌افزار چه مفهومی دارد.

---

# استاندارد چیست؟

فرض کنید چندین شرکت مختلف تصمیم بگیرند مرورگری برای وب تولید کنند.

اگر هر شرکت زبان JavaScript را مطابق سلیقه خود طراحی کند، نتیجه چه خواهد بود؟

ممکن است کدی که در یک مرورگر اجرا می‌شود، در مرورگر دیگر خطا تولید کند.

در چنین شرایطی، توسعه نرم‌افزار تقریباً غیرممکن خواهد شد.

برای جلوگیری از این مشکل، لازم است مجموعه‌ای از قوانین مشترک وجود داشته باشد که همه پیاده‌سازی‌ها از آن پیروی کنند.

به این مجموعه قوانین **استاندارد** گفته می‌شود.

استاندارد مشخص می‌کند:

- سینتکس زبان چگونه باشد.
- کلمات کلیدی چه معنایی داشته باشند.
- عملگرها چگونه رفتار کنند.
- انواع داده چه ویژگی‌هایی داشته باشند.
- اشیای داخلی زبان چگونه عمل کنند.

به بیان دیگر، استاندارد تعیین می‌کند **زبان چگونه باید رفتار کند**؛ اما مشخص نمی‌کند این رفتار چگونه پیاده‌سازی شود.

---

# ECMAScript استاندارد JavaScript است

اکنون می‌توانیم تعریف دقیق‌تری ارائه کنیم.

**ECMAScript مشخصات رسمی (Specification) زبان JavaScript است.**

این استاندارد توضیح می‌دهد که یک موتور JavaScript باید چگونه زبان را پیاده‌سازی کند.

به همین دلیل، وقتی درباره JavaScript صحبت می‌کنیم، در واقع درباره زبانی صحبت می‌کنیم که مطابق استاندارد ECMAScript پیاده‌سازی شده است.

---

## تعریف ساده

ECMAScript کتاب قانون زبان JavaScript است.

---

## تعریف فنی

ECMAScript مجموعه‌ای از مشخصات فنی (Language Specification) است که رفتار رسمی زبان را تعریف می‌کند و تمام موتورهای JavaScript موظف‌اند آن را پیاده‌سازی کنند.

---

# یک تشبیه ساده

فرض کنید قصد ساختن یک ساختمان را دارید.

سه جزء مختلف وجود دارند.

## نقشه ساختمان

نقشه مشخص می‌کند:

- ساختمان چند طبقه باشد.
- اتاق‌ها چگونه طراحی شوند.
- ستون‌ها کجا قرار بگیرند.

اما خود نقشه ساختمان نیست.

---

## مهندس اجرا

مهندس با استفاده از همان نقشه، ساختمان را می‌سازد.

ممکن است شرکت‌های مختلف همان نقشه را اجرا کنند، اما روش اجرای آن‌ها متفاوت باشد.

---

در JavaScript نیز دقیقاً همین اتفاق رخ می‌دهد.

ECMAScript نقش **نقشه ساختمان** را دارد.

JavaScript Engine همان **مجری ساختمان** است.

---

# چرا نام آن JavaScript نیست؟

شاید این سؤال برایتان پیش آمده باشد که اگر ECMAScript همان استاندارد JavaScript است، چرا نام آن JavaScript نیست؟

پاسخ این سؤال ریشه‌ای تاریخی دارد.

در سال‌های ابتدایی توسعه JavaScript، شرکت Netscape تصمیم گرفت مشخصات زبان را به یک سازمان استانداردسازی بین‌المللی واگذار کند تا توسعه زبان وابسته به یک شرکت خاص نباشد.

این استاندارد بعدها با نام **ECMAScript** منتشر شد.

از آن زمان تاکنون، JavaScript بر اساس این استاندارد توسعه پیدا می‌کند.

بنابراین:

- JavaScript نام زبان است.
- ECMAScript نام استاندارد آن زبان است.

---

# آیا JavaScript همان ECMAScript است؟

اکنون می‌توانیم پاسخ این سؤال را دقیق‌تر بیان کنیم.

خیر.

JavaScript و ECMAScript یکسان نیستند.

رابطه آن‌ها شبیه رابطه این دو مفهوم است:

- زبان فارسی
- دستور زبان فارسی

دستور زبان مشخص می‌کند که جملات چگونه ساخته شوند.

اما دستور زبان، خود زبان نیست.

در JavaScript نیز ECMAScript مشخص می‌کند که زبان چگونه باید رفتار کند.

---

# چه کسانی ECMAScript را توسعه می‌دهند؟

استاندارد ECMAScript توسط گروهی از متخصصان صنعت توسعه داده می‌شود که با نام **TC39** شناخته می‌شوند.

اعضای این کمیته از شرکت‌های مختلفی مانند:

- Google
- Microsoft
- Apple
- Mozilla
- Meta
- Oracle

و بسیاری از سازمان‌های دیگر تشکیل شده‌اند.

وظیفه این کمیته بررسی، طراحی و تصویب قابلیت‌های جدید زبان است.

هر ویژگی جدید JavaScript، پیش از آنکه وارد مرورگرها شود، ابتدا باید مراحل مختلف بررسی و تصویب را در TC39 طی کند.

به همین دلیل، توسعه JavaScript فرآیندی کاملاً کنترل‌شده و استاندارد است.

---

# نسخه‌های ECMAScript

احتمالاً نام‌هایی مانند موارد زیر را شنیده‌اید:

- ES5
- ES6
- ES2017
- ES2020
- ES2023

همه این نام‌ها به نسخه‌های مختلف استاندارد ECMAScript اشاره دارند.

برای مثال، نسخه ES2015 که بیشتر با نام **ES6** شناخته می‌شود، یکی از مهم‌ترین نسخه‌های تاریخ JavaScript است.

قابلیت‌هایی مانند:

- let
- const
- Arrow Function
- Class
- Template Literals
- Promise
- Module

برای نخستین بار در این نسخه به استاندارد اضافه شدند.

از سال ۲۰۱۵ به بعد، به‌جای انتشار نسخه‌های بزرگ و نامنظم، استاندارد ECMAScript تقریباً هر سال یک نسخه جدید منتشر می‌کند.

این روند باعث شده زبان JavaScript بدون ایجاد تغییرات ناگهانی، به‌صورت پیوسته تکامل پیدا کند.

---

# نکته مهندسی

یکی از مهم‌ترین ویژگی‌های ECMAScript، **Backward Compatibility** است.

این اصل بیان می‌کند که نسخه‌های جدید زبان تا حد امکان نباید باعث از کار افتادن کدهای قدیمی شوند.

به همین دلیل، امروزه هنوز میلیون‌ها برنامه JavaScript که سال‌ها پیش نوشته شده‌اند، بدون تغییر در مرورگرهای مدرن اجرا می‌شوند.

این تصمیم نقش مهمی در موفقیت JavaScript داشته است؛ زیرا وب نمی‌تواند هر چند سال یک‌بار تمام نرم‌افزارهای خود را بازنویسی کند.

# JavaScript Runtime Environment چیست؟

تا اینجا میان **JavaScript، ECMAScript و JavaScript Engine** تفاوت قائل شدیم.

اما یک مفهوم دیگر نیز وجود دارد: **Runtime Environment**.

Runtime محیطی است که JavaScript در آن اجرا می‌شود و علاوه بر Engine، امکانات و APIهای مورد نیاز برنامه را نیز در اختیار کد قرار می‌دهد.

بنابراین می‌توان یک مدل ذهنی ساده به این شکل داشت:

```text
JavaScript
    ↓
ECMAScript
    ↓
JavaScript Engine
    ↓
Runtime Environment
```

در این مدل:

- **JavaScript** زبان برنامه‌نویسی است.
- **ECMAScript** مشخصات رسمی بخش زبانی آن را تعریف می‌کند.
- **JavaScript Engine** کد JavaScript را پردازش و اجرا می‌کند.
- **Runtime Environment** محیطی است که Engine را همراه با قابلیت‌های مورد نیاز برای یک محیط خاص فراهم می‌کند.

این تفاوت برای درک اکوسیستم JavaScript بسیار مهم است.

---

## Language و Runtime یکسان نیستند

برای مثال، قابلیت‌هایی مانند `Array` و `Promise` بخشی از محیط زبانی استاندارد JavaScript هستند؛ اما قابلیت‌هایی مانند دسترسی به فایل‌های سیستم یا APIهای خاص مرورگر به Runtime مربوط می‌شوند.

به همین دلیل، همه قابلیت‌هایی که با JavaScript استفاده می‌کنیم الزاماً بخشی از خود زبان نیستند.

این موضوع در فصل‌های بعد، هنگام بررسی Browser Runtime و Node.js، اهمیت بیشتری پیدا خواهد کرد.

---

# Browser JavaScript چیست؟

یکی از مهم‌ترین Runtimeهای JavaScript، **Browser Runtime** است.

وقتی JavaScript در مرورگر اجرا می‌شود، Engine مسئول اجرای زبان است و Browser نیز مجموعه‌ای از قابلیت‌ها و APIهای مخصوص محیط وب را در اختیار برنامه قرار می‌دهد.

به‌صورت مفهومی:

```text
Browser Runtime
      ↓
JavaScript Engine
      +
Browser APIs
      ↓
Web Application
```

برای مثال، برنامه‌های Browser می‌توانند با قابلیت‌هایی مانند Document و Web APIs با محیط صفحه و مرورگر تعامل داشته باشند.

نکته مهم این است که این قابلیت‌ها را نباید با خود ECMAScript یکی دانست.

موضوع Browser APIs و DOM در بخش **Browser JavaScript and Advanced DOM** به‌صورت کامل بررسی خواهد شد.

---

# Server-Side JavaScript چیست؟

JavaScript محدود به مرورگر نیست.

همین زبان می‌تواند در محیط‌های Server-Side نیز اجرا شود.

در این حالت، Runtime امکاناتی متناسب با نیازهای سمت سرور در اختیار برنامه قرار می‌دهد.

مدل مفهومی آن:

```text
Server Runtime
      ↓
JavaScript Engine
      +
Server APIs
      ↓
Server Application
```

به این ترتیب، یک زبان می‌تواند در Runtimeهای مختلف استفاده شود، در حالی که هر Runtime امکانات مخصوص محیط خود را ارائه می‌کند.

---

# Node.js چیست؟

**Node.js** یکی از شناخته‌شده‌ترین Runtimeهای Server-Side برای اجرای JavaScript خارج از Browser است.

Node.js به JavaScript اجازه می‌دهد در محیط Server اجرا شود و به قابلیت‌هایی دسترسی داشته باشد که برای ساخت برنامه‌های سمت سرور مورد نیاز هستند.

نکته مهم این است که Node.js خود زبان جدیدی نیست.

مدل ذهنی صحیح‌تر:

```text
JavaScript
    ↓
ECMAScript
    ↓
JavaScript Engine
    ↓
Node.js Runtime
    ↓
Server Application
```

بنابراین:

> Node.js یک JavaScript Runtime است، نه یک زبان برنامه‌نویسی مستقل.

جزئیات Runtime و ارتباط آن با Engine در فصل **JavaScript Engine and Runtime** بررسی خواهد شد.

---

# Modern JavaScript چیست؟

JavaScript یک زبان ثابت نیست.

استاندارد ECMAScript به‌صورت پیوسته توسعه پیدا می‌کند و قابلیت‌های جدیدی به زبان اضافه می‌شوند.

از سال ۲۰۱۵، انتشار سالانه استاندارد باعث شده JavaScript به‌صورت تدریجی و پیوسته تکامل پیدا کند.

به همین دلیل، اصطلاح **Modern JavaScript** معمولاً به مجموعه قابلیت‌ها و الگوهای امروزی زبان اشاره دارد که در نسخه‌های جدید ECMAScript و اکوسیستم مدرن JavaScript مورد استفاده قرار می‌گیرند.

برای مثال:

```javascript
const userName = "Omid";

const message = `Hello, ${userName}`;
```

در این مثال از قابلیت‌هایی استفاده شده که در JavaScript مدرن رایج هستند.

هدف این فصل آموزش Syntax مدرن نیست.

موضوع Modern JavaScript در فصل **Modern JavaScript Syntax** به‌صورت مستقل و عملی بررسی خواهد شد.

---

# چرا Fundamentals JavaScript اهمیت دارد؟

شناخت Syntax به‌تنهایی برای تبدیل شدن به یک توسعه‌دهنده حرفه‌ای کافی نیست.

یک توسعه‌دهنده باید بتواند میان مفاهیم مختلف ارتباط برقرار کند.

برای مثال:

```text
Language
   ↓
ECMAScript
   ↓
Engine
   ↓
Runtime
   ↓
Application
```

اگر این لایه‌ها را از یکدیگر تفکیک نکنیم، در فصل‌های بعدی هنگام مواجهه با موضوعاتی مانند Scope، Execution Context، Call Stack، DOM و Asynchronous JavaScript با سوءبرداشت‌های مختلف روبه‌رو خواهیم شد.

Fundamentals در واقع پایه‌ای است که این مدل ذهنی روی آن ساخته می‌شود.

---

# Language vs Runtime؛ یک مدل ذهنی حرفه‌ای

برای یک توسعه‌دهنده حرفه‌ای، یکی از مهم‌ترین تفکیک‌ها این است:

```text
Language
    ↓
Rules and Semantics

Runtime
    ↓
Execution + Host Capabilities
```

زبان مشخص می‌کند کد چه معنا و رفتاری دارد.

Runtime مشخص می‌کند این کد در چه محیطی اجرا می‌شود و چه قابلیت‌هایی در اختیار آن قرار می‌گیرد.

بنابراین ممکن است یک مفهوم در زبان JavaScript وجود داشته باشد، اما یک API خاص فقط در یک Runtime در دسترس باشد.

این تفکیک بعداً هنگام کار با Browser، Node.js و سایر Runtimeها اهمیت زیادی پیدا خواهد کرد.

---

# یک نگاه کوتاه به پشت صحنه

در این فصل فقط یک مدل ذهنی اولیه از اجرای JavaScript می‌سازیم:

```text
Source Code
     ↓
JavaScript Engine
     ↓
Processing
     ↓
Execution
     ↓
Runtime Environment
     ↓
Application Behavior
```

در این فرآیند، Engine مسئول اجرای بخش زبانی JavaScript است و Runtime محیط و قابلیت‌های مورد نیاز برنامه را فراهم می‌کند.

جزئیات داخلی این فرآیند، از جمله Parsing، AST، Compilation، Execution، Optimization و JIT، در فصل **JavaScript Engine and Runtime** بررسی خواهد شد.

هدف این فصل فقط این است که بدانیم JavaScript یک زبان است که درون یک Runtime و توسط یک Engine اجرا می‌شود.

---

اکنون که تفاوت JavaScript و ECMAScript را می‌دانیم، پرسش مهم‌تری مطرح می‌شود.

اگر ECMAScript فقط یک استاندارد است، پس چه چیزی کد JavaScript را واقعاً اجرا می‌کند؟

هنگامی که دکمه **Run** را فشار می‌دهیم یا صفحه‌ای در مرورگر باز می‌شود، چه نرم‌افزاری این کدها را می‌خواند، تفسیر می‌کند و در نهایت به برنامه‌ای قابل اجرا تبدیل می‌کند؟

پاسخ این پرسش ما را با یکی از مهم‌ترین اجزای اکوسیستم JavaScript، یعنی **JavaScript Engine** آشنا خواهد کرد.

# خلاصه فصل

در این فصل با یکی از بنیادی‌ترین پرسش‌های دنیای برنامه‌نویسی آشنا شدیم:

> **JavaScript چیست؟**

در نگاه اول ممکن است پاسخ این سؤال بسیار ساده به نظر برسد، اما مشاهده کردیم که تعریف دقیق JavaScript تنها با جمله «زبان برنامه‌نویسی صفحات وب» کامل نمی‌شود.

JavaScript امروزه یک زبان برنامه‌نویسی همه‌منظوره است که در محیط‌های مختلف اجرا می‌شود و بر اساس استاندارد **ECMAScript** توسعه می‌یابد. این زبان به گونه‌ای طراحی شده است که ضمن سادگی، انعطاف‌پذیری بالایی داشته باشد و برنامه‌نویس بتواند از سبک‌های مختلف برنامه‌نویسی برای حل مسائل استفاده کند.
همچنین دیدیم که JavaScript یک زبان Dynamic است و اجرای آن را نمی‌توان صرفاً با برچسب «Interpreted» توضیح داد؛ موتورهای مدرن از Compilation و JIT نیز استفاده می‌کنند. در نهایت، میان Language، Engine و Runtime تفاوت گذاشتیم و دیدیم که JavaScript می‌تواند در Browser و Server اجرا شود.


در ادامه نیز با مهم‌ترین ویژگی‌های ذاتی JavaScript آشنا شدیم و دیدیم که بسیاری از اصطلاحاتی که معمولاً تنها حفظ می‌شوند، در واقع مفاهیم بسیار عمیقی هستند که در فصل‌های بعدی بارها با آن‌ها روبه‌رو خواهیم شد.

# نکات کلیدی فصل (Key Takeaways)

در پایان این فصل باید نکات زیر را به‌خوبی درک کرده باشید:

- JavaScript یک زبان برنامه‌نویسی است، نه صرفاً زبان صفحات وب.
- JavaScript بر اساس استاندارد ECMAScript توسعه پیدا می‌کند.
- ECMAScript خود زبان نیست، بلکه مشخصات رسمی (Specification) زبان را تعریف می‌کند.
- JavaScript یک زبان **High-Level** است؛ یعنی بسیاری از جزئیات سخت‌افزار و مدیریت حافظه را از برنامه‌نویس پنهان می‌کند.
- JavaScript یک زبان **Multi-Paradigm** است و از برنامه‌نویسی رویه‌ای، شیءگرا و تابعی پشتیبانی می‌کند.
- شیءگرایی در JavaScript بر پایه **Prototype** طراحی شده است و نه بر پایه Class.
- کلاس‌ها در JavaScript تنها یک نگارش ساده‌تر برای کار با Prototype هستند.
- JavaScript یکی از انعطاف‌پذیرترین زبان‌های برنامه‌نویسی مدرن است و همین ویژگی نقش مهمی در موفقیت آن داشته است.
- JavaScript یک زبان Dynamically Typed است؛ یعنی Type به Value مربوط است و بررسی Type در Runtime انجام می‌شود.
- JavaScript را نباید صرفاً یک زبان Interpreted دانست؛ موتورهای مدرن از Compilation و JIT نیز استفاده می‌کنند.
- JavaScript Engine مسئول پردازش و اجرای کد است، در حالی که Runtime Environment محیط و قابلیت‌های مورد نیاز برنامه را فراهم می‌کند.
- JavaScript می‌تواند در Runtimeهای مختلف مانند Browser و Node.js اجرا شود.
- Modern JavaScript نتیجه تکامل پیوسته استاندارد ECMAScript و اکوسیستم JavaScript است.

# پاسخ‌های طلایی مصاحبه (Golden Answers)

## JavaScript چیست؟

JavaScript یک زبان برنامه‌نویسی High-Level، Multi-Paradigm و Prototype-Based است که بر اساس استاندارد ECMAScript توسعه یافته است.

---

## ECMAScript چیست؟

ECMAScript مشخصات رسمی زبان JavaScript را تعریف می‌کند و تمام پیاده‌سازی‌های JavaScript باید از این استاندارد پیروی کنند.

---

## منظور از High-Level چیست؟

High-Level بودن به این معناست که زبان بسیاری از پیچیدگی‌های سخت‌افزار و مدیریت حافظه را از برنامه‌نویس پنهان می‌کند تا تمرکز او بر حل مسئله باشد.

---

## Multi-Paradigm یعنی چه؟

یعنی JavaScript محدود به یک سبک برنامه‌نویسی نیست و از برنامه‌نویسی رویه‌ای، شیءگرا و تابعی پشتیبانی می‌کند.

---

## آیا JavaScript شیءگرا است؟

بله. JavaScript یک زبان شیءگرا است، اما مدل شیءگرایی آن بر پایه Prototype پیاده‌سازی شده است، نه Class.

---


---

## Dynamic Typing چیست؟

JavaScript یک زبان Dynamically Typed است؛ یعنی Type به Value مربوط است و یک Variable می‌تواند در زمان‌های مختلف Valueهایی با Typeهای متفاوت نگه‌داری کند.

---

## آیا JavaScript فقط Interpreted است؟

خیر. این توصیف بیش از حد ساده است؛ موتورهای مدرن JavaScript از تکنیک‌هایی مانند Compilation و JIT برای پردازش و اجرای بهینه کد استفاده می‌کنند.

---

## JIT Compilation چیست؟

JIT یا Just-In-Time Compilation تکنیکی است که در زمان اجرای برنامه به موتور اجازه می‌دهد بخش‌هایی از کد را بر اساس اطلاعات Runtime به شکل کارآمدتری کامپایل و بهینه کند.

---

## تفاوت JavaScript Engine و Runtime چیست؟

Engine مسئول پردازش و اجرای کد JavaScript است، در حالی که Runtime محیط اجرای کامل‌تری است که Engine و قابلیت‌ها و APIهای متناسب با یک محیط خاص را در اختیار برنامه قرار می‌دهد.

---

## Browser Runtime و Server-Side Runtime چه تفاوتی دارند؟

هر دو JavaScript را اجرا می‌کنند، اما قابلیت‌های Host آن‌ها متفاوت است. Browser Runtime برای محیط وب و تعامل با Browser APIs طراحی شده است، در حالی که Server-Side Runtime قابلیت‌های مورد نیاز برنامه‌های سمت سرور را فراهم می‌کند.

---

## Node.js چیست؟

Node.js یک JavaScript Runtime برای اجرای JavaScript خارج از Browser و به‌ویژه در محیط Server است؛ بنابراین Node.js یک زبان مستقل نیست.

---

## Modern JavaScript چیست؟

Modern JavaScript به قابلیت‌ها و الگوهای امروزی JavaScript اشاره دارد که در نتیجه تکامل پیوسته ECMAScript و اکوسیستم این زبان شکل گرفته‌اند.

## تفاوت JavaScript و ECMAScript چیست؟

JavaScript زبان برنامه‌نویسی است، در حالی که ECMAScript استانداردی است که رفتار رسمی این زبان را تعریف می‌کند.

---

# جمع‌بندی فصل

این فصل نقطه شروع سفر ما در یادگیری JavaScript بود.

در این فصل هنوز حتی یک برنامه واقعی ننوشتیم و عمداً وارد مباحثی مانند متغیرها، توابع یا انواع داده نشدیم. دلیل این تصمیم آن بود که پیش از یادگیری سینتکس، باید بدانیم دقیقاً با چه زبانی روبه‌رو هستیم و این زبان بر چه اصولی بنا شده است.

در فصل‌های بعد، به‌تدریج وارد اجزای تشکیل‌دهنده JavaScript خواهیم شد و خواهیم دید که چگونه همین مفاهیم بنیادین، رفتار تمام بخش‌های زبان را شکل می‌دهند.

اگر مفاهیم این فصل را به‌خوبی درک کرده باشید، ادامه مسیر یادگیری JavaScript برای شما بسیار ساده‌تر، منطقی‌تر و عمیق‌تر خواهد بود.
